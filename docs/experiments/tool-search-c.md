# 实验 C：最小常驻工具与按需发现

基线提交：`a9cca3a`。开发分支：`codex/tool-search-c`。

## 行为与范围

主 Agent 默认只提供 `respond`、`read_recent_messages`、`tool_search`；主动介入另提供 `remain_silent`。`answer_question`、`summarize_history`、`set_reminder` 和已配置的九个 `maps_*` 工具通过本地关键词/名称/描述检索发现。没有配置高德密钥时不会注册或发现高德能力。

每次检索最多返回三项，下一轮才将其完整参数定义加入模型目录与输出约束。搜索本身不执行历史查询、提醒写入或高德请求；结果不重复返回完整 Schema。可继续检索详情、坐标和路线，已加载工具只在本次执行有效。请求间不共享可变加载状态。零命中会提供改写提示；重复搜索不会重复添加工具。

工具执行仍经过统一 Registry 的参数、权限和业务校验。尚未加载的工具即使被模型直接输出，也只获得可修复拒绝，不会调用外部服务。主动介入发现提醒工具不产生写入授权。仅加载相关高德工具后才追加地图/卡片规则；仅加载时间总结能力后才追加完整时间范围及禁止绕过规则。终局回答仍保留本次已激活能力的证据规则。

与 B 使用相同高德词表、匹配、排序、返回上限和预算口径：普通业务最多三轮；发现任意高德能力后最多八轮业务；本次最多三次发现尝试，按实际调用增加额度；最后另有一轮仅回答/沉默。发现失败和零命中仍计入发现次数，不能靠搜索无限延长。

生产模块显式注册 `tool_search`。不注册发现工具的内部测试或自定义 Registry 保持此前完整目录行为，便于保留原基线并复用现有能力测试。

## 固定离线案例与测量

复现：

```sh
cd services/api
go test -run TestDiscoveryMeasurement -v ./internal/ai/agent/main
```

测试包含相同的十条问题，使用六个通用工具与九个高德工具的真实定义、固定用户消息与时间。`llm.InputTokenUpperBound` 是系统使用的保守输入字节上界估算，**不是模型实际 token 数**。表中搜索次数为预定路径，不是模型实测路由成功率。

| 案例 | A 首轮估算 | C 首轮估算 | 预定发现次数 |
|---|---:|---:|---:|
| 你好 | 24035 | 8907 | 0 |
| 上次约好几点见面 | 24053 | 8925 | 1 |
| 总结昨天聊了什么 | 24053 | 8925 | 1 |
| 明天早上九点提醒我喝水 | 24062 | 8934 | 1 |
| 上海今天天气 | 24047 | 8919 | 1 |
| 上海找一家清淡餐厅 | 24056 | 8928 | 1 |
| 查询这个地点的营业时间 | 24062 | 8934 | 1 |
| 从五角场步行去复旦大学 | 24062 | 8934 | 1 |
| 附近吃什么（缺位置，先澄清） | 24044 | 8916 | 0 |
| 找上海餐厅，查详情并规划步行路线 | 24077 | 8949 | 3 |

单看普通聊天首轮，估算减少约 62.9%。

另以脚本模型与相同的模拟高德返回执行“搜索餐厅 → 查详情 → 步行路线 → 回答”，真实经过主循环、工具参数校验和结果裁剪：

| 模式 | 模型轮次 | 首轮估算 | 累计输入估算 | 高德业务调用 |
|---|---:|---:|---:|---:|
| A 完整默认目录 | 4 | 24077 | 98143 | 3 |
| C 最小常驻集合 | 7 | 8949 | 101155 | 3 |

这条固定链累计估算增加约 3.1%，说明多次发现会抵消首轮节省，不能只凭首轮估算判断所有场景收益。脚本模型保证按预定路径选择工具，不能证明真实模型的检索召回、任务成功率、回答质量或耗时。尚未调用线上模型或真实高德服务，尚未部署。
