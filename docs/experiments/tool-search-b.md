# 实验 B：高德工具按需加载

基线提交：`a9cca3a`。本分支：`codex/tool-search-b`。同实验 C 使用相同十条问题、生产工具 Schema、固定上下文和高德假响应，地图检索关键词、排序、最多三项结果的规则相同。

## 行为

- 常驻 `respond`、`read_recent_messages`、`answer_question`、`summarize_history`、`set_reminder`、`tool_search`；`remain_silent` 仅主动介入开放。
- 高德九个工具在服务端保留注册及原授权逻辑，但默认不向模型提供完整定义。搜索按名称、描述及中英文关键词本地匹配，不调用额外模型或向量服务。
- 搜索只返回名称、描述；命中工具的参数 Schema 加入本次运行后续轮次的工具目录及输出约束。任一高德工具命中后才加载完整高德定位、证据、卡片和安全规则。
- 每次运行独立保存加载集合；重复搜索不会重复注入；可继续发现详情或路线能力。目录之外的工具选择会被本地拦截，不执行业务调用。
- 原业务额度为普通三轮、高德八轮，搜索按实际发生额外增加额度，最多三次（含无结果或参数错误）；最后另有一次只允许回答/静默的收尾轮。展开工具目录和加入观察结果后继续检查硬预算。
- 高德密钥未配置时搜索只返回空结果，不会注册不存在的高德能力。独立调用方未注册 `tool_search` 时继续使用原完整目录，便于保持既有调用语义。

普通首轮估算减少约 **41.3%**。

另实际执行“地点搜索 → 地点详情 → 步行路线 → 回答”的同一假模型/假高德链，B 在每次业务调用前分别发现对应工具：

| 方案 | 模型轮数 | 首轮估算 | 累计输入估算 | 外部调用次数 |
|---|---:|---:|---:|---:|
| A 完整目录 | 4 | 24077 | 98143 | 3 |
| B 高德按需 | 7 | 14139 | 133635 | 3 |

这条链中累计输入反而增加约 **36.2%**：每次工具发现增加一个模型轮次。首轮节省不能直接解释为整次请求节省。合并相关能力查询可能减少轮数，但本次保持 B/C 固定三次发现，便于公平比较。
