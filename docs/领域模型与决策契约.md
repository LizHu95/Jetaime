# 领域模型与决策契约

本文集中维护业务对象、授权关系、决策输入输出与规划/分享扩展边界。当前代码为 Go 类型定义，不是数据库实体；字段以对应 types.go 为准。已有结构校验、空间收藏授权、Session 反馈投影和基于可信评估的 outcome 校验；尚无 Workflow、事实提取与语义判定器、持久化或生产授权入口。下文的首轮业务规则已确定，实现边界见第 8 节。

## 1 领域对象与多空间关系

| 对象 | 作用 | 当前状态 |
| --- | --- | --- |
| User | 身份主体 | 首轮仅用用户 ID，真实资料未建模 |
| Space、Member | 空间与用户成员关系 | personal/couple，owner/member 角色已定义 |
| Note | 创建者拥有的独立正文 | 五类：restaurant、recipe、activity、movie、other |
| SpaceNote | 空间收藏关系 | SpaceID、NoteID、AddedBy；联合唯一由未来存储实现 |
| Memory | 个人长期记忆 | 类型、强度、来源、推断确认状态已定义 |
| Decision | 一次生成结果与历史快照 | 类型已定义，CLI 可先留内存/文件 |

关系为 User ↔ Member ↔ Space ↔ SpaceNote ↔ Note，Note 单独保留 CreatorID。用户可创建/加入多个空间，不能在用户上写唯一 SpaceID；自动个人空间只是默认入口。一个 Note 可被多个空间引用，不在正文上绑定唯一空间。

个人空间只有本人，couple 最多两人；限制按类型判断，不能把“最多两人”写成所有空间通用规则。未来 group 类型和成员参与选择按功能增加；空间成员身份不等于正文所有权。

首轮正文编辑/删除仅作者允许；owner/member 均可移除空间收藏；新增收藏由下节的作者授权规则决定，移除 SpaceNote 不删除 Note。创建者是唯一 owner，负责邀请，member 不管理成员。个人空间只有创建者，情侣空间可先一人、最多两人，用户可属于多个空间。V1 不实现 owner 转移。成员角色不授予正文编辑权。

创建配额在 API 阶段确定，不设用户唯一空间限制。Note 修改影响引用空间，历史保留当时快照。删除和权限撤回的未来访问、召回与历史保留策略在存储阶段落实。

## 2 分享与市场扩展

| 操作 | 关系与归属 |
| --- | --- |
| 收藏到空间 | 新建 SpaceNote，引用同一 Note；不转移作者或编辑权 |
| 复制为我的笔记 | 新建 Note，由复制者拥有并记录来源；独立编辑 |
| 分享或公开发布 | 另有授权/发布状态，不等于任意人可修改 |

V1 只有作者可将自己的 Note 收藏到本人所属空间，SpaceNote.AddedBy 必须等于 Note.CreatorID。这项主动操作即授予该空间当前成员读取与决策使用权；后加入的成员同样可读，界面需明确告知收藏会对空间成员可见。作者仍拥有正文。成员可移除收藏，移除即撤销该空间通过此关系获得的未来读取与召回权限。

读取要求有效正文、有效收藏与当前成员身份；知道 NoteID 不授予权限。成员读取他人 Note 后，不能再收藏到其他空间或复制正文；作者可以向多个所属空间分别授权。个人空间内的收藏不自动分享。V1 的空间内授权以 SpaceNote 表达，不提前新增公共分享模型；来源授权契约现在以 CollectionAuthorization 预留，市场阶段再增加真实分享/发布授权与可转收藏许可。CanCollectIn/CanReadIn/CanRemoveIn 处理可信快照，服务端负责获取真实关系和剔除已删除正文。

CollectionAuthorization 是服务端组装的授权值对象，不是客户端请求字段或数据库分享实体：Source 表达来源，NoteID、UserID、TargetSpaceID 将授权限定到指定笔记、操作人和目标空间。本期 CollectionSource 只声明 author，不提前声明可用的 share/publication。

调用顺序：从可信存储获取 Note 和目标空间成员 → 使用真实 actorID 调用 Note.AuthorizeAuthorCollection → 将授权传入 Note.CanCollectIn → 保存 SpaceNote。AuthorizeAuthorCollection 核验正文及作者身份，CanCollectIn 再核验授权来源、范围与实时目标成员快照；即使手工构造 Source=author，非作者也会被拒绝。授权值对象不替代数据库事务：服务端在保存时确保正文和成员版本仍有效。

后续分享/市场通过来源服务核验真实 grant，再扩展来源校验；不能只增加一个枚举值就放行。SpaceNote 当前的读取规则仍是 V1 作者收藏，新增来源时须同步来源引用及撤回后的读取/召回规则。本次不增加 Note.IsPublic，也不开放非作者收藏。

跨空间分享、公开审核、撤回与复制语义尚未建模。建议引用收藏服从最新授权，撤回后停止未来读取和召回；复制保留规则、历史快照的撤回/删除政策另行制定，不承诺作者无法删除敏感内容。解除情侣绑定后的成员访问、数据归属及再次绑定也需明确后才开放。

## 3 Memory

| 字段 | 含义 |
| --- | --- |
| ID、UserID、Content | 记忆标识、所属用户与自然语言内容 |
| Type | preference 喜好排斥；constraint 限制；feedback 历史体验 |
| Strength | low、medium、strong、hard；hard 必须满足 |
| Source | explicit 用户填写；feedback 原始反馈；inferred 系统推断 |
| Confirmed | 主要针对 inferred，用户是否确认推断 |

显式输入直接生效，不依赖 Confirmed；未确认推断不参与决策，确认后生效。Source=feedback 必须 Type=feedback、Strength=low，只作弱参考；从反馈推导偏好需另建 inferred 等待确认。Strength=hard 必须 Type=constraint，不将原始拒绝升级为硬约束。全部适用硬约束独立获取，不依赖语义召回。

AllowedSpaceIDs 表达共同决策的明确授权，空列表为私有。V1 授权同时允许计算及在该空间的结果中展示与本次决策相关的解释，授权界面必须说明接收者是当前空间成员（包括后加入者）。用户不愿披露的内容不授权；本期不提供“仅计算但绝不披露”的模式，因为推荐本身也可能暴露偏好。个人空间可用本人生效记忆；共同空间只用授权到该空间的生效记忆。CanUseIn 只检查生效和使用许可，调用者仍须校验实时成员。撤回后新的上下文和 Session 不继续使用旧记忆；授权不开放完整 Memory 列表，结果仅引用与该决策有关的已授权内容；公开 Reason、ParticipantMatches、Unknowns 和历史说明均受此范围限制。撤回不保证收回对方已经看到的内容。

未授权硬约束不可透传，无法验证必要约束时要求完善共同条件，不能宣称满足。Content 是自然语言，可靠食材和费用校验仍需后续结构化事实。

## 4 决策输入与上下文

| 类型 | 作用 |
| --- | --- |
| Request | SpaceID、可信身份 RequesterID、Task、Query、Conditions、SessionID |
| Conditions | 候选 NoteTypes、预算时长、临时硬约束、软偏好及可选 Planning |
| Participant | 授权参与人及其长期硬约束、相关记忆 |
| Context | 业务组装的任务、条件、参与人和候选事实，供模型使用 |

Task 已声明 select、day_plan、trip_plan，本期 runner 只实现 select，规划类型仅预留。NoteTypes 是内容过滤，空列表不限类型，不表达任务。金额为人民币分、时长为分钟；预算指全体实际参与人的总额，select 指完成一次所选活动的总费用，规划指整套行程总费用；时长指共同活动的经过时间，不乘人数。nil 不限、0 显式零上限、负值非法。人均费用必须按实际人数换算；菜谱缺份数、票价缺人数口径等情形不能直接换算。缺失属性未知，不能当零。

Conditions 中的硬约束属于本次请求，Participant 中属于用户长期记忆，两者都生效。客户端不能提交可信候选或可信参与人；HTTP RequesterID 来自会话。JSON 使用 camelCase，空列表由业务构建为 []。

首轮事实口径：Note.Attributes 可继续承载原始资料，但不能作为无来源的可信事实。独立事实校验器应输出有来源与适用范围的费用（CNY、per_person/total、总价覆盖人数）、活动时长（分钟）、饮食/成分等事实及确认状态；仅模型提取且未经核验的事实仍为未知。缺少成分不等于不含该成分，商户历史价格不等于当前可靠总价。自然语言硬约束未能可靠归一化时先要求补充或确认，不能默认为 satisfied。Mock 阶段使用人工核验事实和固定评估状态，真实事实适配器后续实现。

## 5 结果选项与反馈

```text
Result.Options                   多个替代方案
└── Option：OptionID、Title、Reason、ParticipantMatches、Unknowns
    └── 必须且只能填写一个内容
        ├── Selection.NoteID     select：一个合法候选
        └── Itinerary            规划：一套完整行程
            └── Days[] → Items[] 多天与按序执行的步骤
```

select 最多三个 Option，每个一个 Note；一天或多日计划每个 Option 含多项，行程项数不受 Top 3 限制。规划备选数按后续评测确定。OptionID 由服务端在模型响应解码后、最终 Result 校验前分配，在 Decision 内唯一，不要求模型生成可信 ID。

Result outcome 为 recommended、no_candidates、constraint_conflict、insufficient_information。recommended 至少一项；其他结果 Options 为空并解释原因；调用失败返回错误，不伪造 Result。先由服务端判定，模型不能自行改写 outcome。

候选对全部适用硬约束的汇总状态为 satisfied / violated / unknown：任一已知违反优先于未知；没有硬约束时视为 satisfied。只有 satisfied 可以进入可采纳选项；未知软信息允许出现在 Unknowns，未知硬信息不能用免责声明代替满足。即使其他候选满足，未知候选也不可混入推荐。

| 顺序 | 服务端判定 | outcome |
| --- | --- | --- |
| 1 | 已确认的本次条件与适用长期硬约束存在确定矛盾 | constraint_conflict |
| 2 | 授权、类型过滤与 Session 排除后的完整候选池为空 | no_candidates |
| 3 | 至少一个候选满足全部硬约束 | recommended，仅从满足集合选取 |
| 4 | 无满足项，但至少一个候选尚无已知违反、只有必要事实未知 | insufficient_information，提示补充事实 |
| 5 | 候选非空且每个都有已知硬约束违反 | constraint_conflict，说明是候选无法满足而非一定输入自相矛盾 |

判定覆盖完整合法候选池，不能将向量 Top K 漏召当成无候选或冲突；必要时回退全量。判定为 recommended 但召回子集无满足项时须重召回，不能返回空推荐。SelectEvaluation 只消费服务端可信汇总状态，校验结果与状态一致，不负责从自然语言证明事实。

Feedback 关联 DecisionID + OptionID，含 UserID、Action、Reason、CreatedAt。adopt/reject 必须针对该决策的选项，change_batch 不指定 OptionID。拒绝整套计划不等于拒绝所有组成 Note。

同一 Decision 最多一个批次内采纳项；同一 Session 另维护跨批次当前采纳 OptionRef（DecisionID、OptionID 与 select 的 NoteID）。任一实际参与人可改选，表示共同结果可被任一人操作，不代表双方一致表决。最后接收的 adopt 生效，保留历史事件。批次历史中 reject 当前采纳项清除该批次采纳，拒绝其他项不影响该批次采纳，change_batch 不清除采纳。按服务端接收顺序处理，不按客户端时间排序。

ApplyFeedback 检查参与人及选项归属；同事件 ID 同内容重试不重复写入，不同内容报冲突。CreatedAt 由服务端生成，重试不因新时间另建事件。调用者每次仍须校验实时成员和可信 actorID；存储阶段补充并发排序、唯一性和事务。

Decision.SessionID 保存所属会话，不依赖 LatestDecisionID 反查。反馈人可与 Session.RequesterID 不同；仍要求是 Decision 实际参与人且当前属于空间。有效 Session 中，旧批次 adopt/reject 仍按接收顺序更新当前采纳和排除集合；reject 将 Selection.NoteID 临时排除，如果当前采纳引用同一 Note（即使来自另一批次）也清除。重新采纳取消排除，服务端须重新检查当前来源授权和适用硬约束。Session 过期后 adopt/reject 只更新可访问 Decision 的历史，不复活或修改过期会话，也不传递到新会话。

change_batch 只能针对有效 Session 的最新批次；旧批次命令报状态冲突，历史事件同 ID 重试仍幂等。该事件只是换批请求记录，不代表生成成功；新 Decision 成功保存后才更新 LatestDecisionID、已推荐集合。失败保留旧组，重试沿用命令幂等 ID 并恢复生成状态；服务端在同一事务保存事件、Session 投影及生成命令状态，模型调用放在事务外。业务服务通过 ApplyDecisionFeedback 处理反馈，避免只调用批次级 ApplyFeedback 而遗漏会话投影。ApplyDecisionFeedback 实现内存反馈投影，生成与失败恢复仍待 Workflow。换批不清除采纳、只降低重复排序；排除是明确拒绝，已推荐不等于排除。规划整体拒绝不排除所有组成 Note，反馈不直接修改 Memory。

## 6 规划契约

PlanningConditions 预留明确日期范围、IANA 时区、可选准确时间窗口、出发地、目的地与 relaxed/balanced/packed 节奏。日期为本地 YYYY-MM-DD，包含首尾；day_plan 日期相同，trip_plan 多日。国庆等名称须确认年份和日期，不能假定法定假期。

Itinerary 包含时区、Days 与估计总费用；PlanDay 有本地日期与 Items。PlanItem 有 ItemID、Kind、NoteID、Title、Location、Window、估计费用和 Unknowns。note 项引用候选，break/transfer 不指定 NoteID，不能借此虚构商户。

未来规划校验包括日期时区有效、时间窗口有序且不冲突、费用按全程汇总、转场休息合理、全部参与人约束满足。未知交通票价和营业信息不能视为已验证；跨夜、多时区、每天窗口、住宿与实时信息另行细化。ItemID 为后续局部替换预留，本期反馈仍只针对整体 Option。

## 7 历史与短期状态

Decision 保存输入、参与人 ID、候选事实、Result 和反馈，不默认保存完整 Context 或所有私人记忆。嵌套 map/slice 需复制成快照；数据库映射、保留期限和授权撤回时的历史访问规则尚未实现。

Session 保存当前条件、已推荐/排除 ID 与过期时间，绑定身份、空间和任务；切换后不复用，换批生成新的 Decision。Query 或规范化 Conditions 改变时创建新 Session，旧会话采纳、已推荐和排除集合不继承；纯换批沿用原 Session。比较时集合型列表忽略顺序和重复，自然语言列表及 Query 忽略首尾空白，nil/空列表等价；数值 nil 与 0 不等价，Query 改写不做语义等价猜测。客户端提交旧 SessionID 加新条件时返回需新建会话的错误，不悄悄改旧状态。成员集合变化关闭旧 Session；记忆授权撤回或硬约束修改使受影响 Session 失效，重新授权组装。未来规划还需已看方案摘要，不能仅排除全部使用过的 Note。

业务类型首轮不额外补 Note/Memory 时间字段；已有 Decision/Feedback.CreatedAt 和 Session.ExpiresAt 保留。实现列表、时效和存储时再补必要时间字段，UpdatedAt 不代替并发 Version。

## 8 实现边界与剩余工作

已实现 Space.ValidateMembers、Note.Validate/CanEdit/AuthorizeAuthorCollection/CanCollectIn、CollectionAuthorization.ValidateFor、SpaceNote.CanReadIn/CanRemoveIn、Memory.Validate/IsActive/CanUseIn、Request/Conditions.ValidateSelect、Result.ValidateSelect、SelectEvaluation.Outcome/ValidateResult、Session.ValidateFor/ApplyDecisionFeedback 和 Decision.ApplyFeedback/AdoptedOptionID。

这些函数处理受信快照，不加载或证明数据库授权。空间读取与再收藏规则、会话条件比较、反馈投影和可信评估 outcome 有行为测试；解释授权范围为产品/API 合同，尚无生成后的披露校验器。Result.ValidateSelect 校验载荷、数量、候选和选项 ID 及参与人匹配，不能证明真实费用、语义硬约束、记忆完整性或实时成员关系；这些由授权服务、Context Builder 和事实校验完成。

空间配额、邀请并发、Note 删除与权限撤回后历史访问、数据保留和解除绑定在 HTTP/存储任务实现前确定。规划与分享市场继续仅保留扩展契约。
