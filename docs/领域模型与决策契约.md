# 领域模型与决策契约

本文集中维护业务对象、授权关系、决策输入输出与规划/分享扩展边界。当前代码为 Go 类型定义，不是数据库实体；字段以对应 types.go 为准。尚无 Workflow、校验器、持久化或生产授权实现。

## 1 领域对象与多空间关系

| 对象 | 作用 | 当前状态 |
| --- | --- | --- |
| User | 身份主体 | 首轮仅用用户 ID，真实资料未建模 |
| Space、Member | 空间与用户成员关系 | personal/couple 已定义；成员角色未定义 |
| Note | 创建者拥有的独立正文 | 五类：restaurant、recipe、activity、movie、other |
| SpaceNote | 空间收藏关系 | SpaceID、NoteID、AddedBy；联合唯一由未来存储实现 |
| Memory | 个人长期记忆 | 类型、强度、来源、推断确认状态已定义 |
| Decision | 一次生成结果与历史快照 | 类型已定义，CLI 可先留内存/文件 |

关系为 User ↔ Member ↔ Space ↔ SpaceNote ↔ Note，Note 单独保留 CreatorID。用户可创建/加入多个空间，不能在用户上写唯一 SpaceID；自动个人空间只是默认入口。一个 Note 可被多个空间引用，不在正文上绑定唯一空间。

个人空间只有本人，couple 最多两人；限制按类型判断，不能把“最多两人”写成所有空间通用规则。未来 group 类型和成员参与选择按功能增加；空间成员身份不等于正文所有权。

建议正文编辑/删除仅作者允许，成员按角色管理收藏；移除 SpaceNote 不删除 Note。Note 修改影响引用它的空间，历史 Decision 保留当时快照。成员角色、创建配额、Note 删除/引用失效策略在存储与接口阶段定稿。

## 2 分享与市场扩展

| 操作 | 关系与归属 |
| --- | --- |
| 收藏到空间 | 新建 SpaceNote，引用同一 Note；不转移作者或编辑权 |
| 复制为我的笔记 | 新建 Note，由复制者拥有并记录来源；独立编辑 |
| 分享或公开发布 | 另有授权/发布状态，不等于任意人可修改 |

读取必须同时满足空间成员权限及笔记有效访问授权，知道 NoteID 不等于有权读取或收藏。市场内容参与决策前先成为合法候选，不能跳过授权边界。

分享授权、公开审核、撤回与复制语义尚未建模。建议引用收藏服从最新授权，撤回后停止未来读取和召回；复制保留规则、历史快照的撤回/删除政策另行制定，不承诺作者无法删除敏感内容。解除情侣绑定后的成员访问、数据归属及再次绑定也需明确后才开放。

## 3 Memory

| 字段 | 含义 |
| --- | --- |
| ID、UserID、Content | 记忆标识、所属用户与自然语言内容 |
| Type | preference 喜好排斥；constraint 限制；feedback 历史体验 |
| Strength | low、medium、strong、hard；hard 必须满足 |
| Source | explicit 用户填写；feedback 原始反馈；inferred 系统推断 |
| Confirmed | 主要针对 inferred，用户是否确认推断 |

显式输入直接生效，不依赖 Confirmed；原始反馈只是事实，一次拒绝不升级为永久排斥。首轮建议未确认推断不参与决策，反馈作弱参考；此默认需在 V1-01 定稿。所有适用硬约束独立取得，不能依赖语义检索是否召回。

个人决策用本人记忆；共同决策只用已授权的相关记忆，参与不等于对方能读取所有私人记忆。共享范围未建模，Mock 必须明确约定授权。Content 是自然语言，可靠的食材/费用校验仍需结构化属性。

## 4 决策输入与上下文

| 类型 | 作用 |
| --- | --- |
| Request | SpaceID、可信身份 RequesterID、Task、Query、Conditions、SessionID |
| Conditions | 候选 NoteTypes、预算时长、临时硬约束、软偏好及可选 Planning |
| Participant | 授权参与人及其长期硬约束、相关记忆 |
| Context | 业务组装的任务、条件、参与人和候选事实，供模型使用 |

Task 已声明 select、day_plan、trip_plan，本期 runner 只实现 select，规划类型仅预留。NoteTypes 是内容过滤，空列表不限类型，不表达任务。金额为人民币分、时长为分钟；nil 不限、0 显式零上限、负值非法。缺失属性未知，不能当零。

Conditions 中的硬约束属于本次请求，Participant 中属于用户长期记忆，两者都生效。客户端不能提交可信候选或可信参与人；HTTP RequesterID 来自会话。JSON 使用 camelCase，空列表由业务构建为 []。

## 5 结果选项与反馈

```text
Result.Options                   多个替代方案
└── Option：OptionID、Title、Reason、ParticipantMatches、Unknowns
    └── 必须且只能填写一个内容
        ├── Selection.NoteID     select：一个合法候选
        └── Itinerary            规划：一套完整行程
            └── Days[] → Items[] 多天与按序执行的步骤
```

select 最多三个 Option，每个一个 Note；一天或多日计划每个 Option 含多项，行程项数不受 Top 3 限制。规划备选数按后续评测确定。OptionID 由服务端分配，在 Decision 内唯一，不要求模型生成可信 ID。

Result outcome 为 recommended、no_candidates、constraint_conflict、insufficient_information。recommended 至少一项；其他结果首轮建议 Options 为空并解释原因；调用失败返回错误，不伪造 Result。具体校验未实现。

Feedback 关联 DecisionID + OptionID，含 UserID、Action、Reason、CreatedAt。adopt/reject 必须针对该决策的选项，change_batch 不指定 OptionID。拒绝整套计划不等于拒绝所有组成 Note。

一组采纳数量、改选撤销及拒绝排除策略待确认。建议 select 每组一个有效采纳项，改选保留历史；明确拒绝本轮排除，普通换批只减少重复。这些建议不能当作已经实现的规则。

## 6 规划契约

PlanningConditions 预留明确日期范围、IANA 时区、可选准确时间窗口、出发地、目的地与 relaxed/balanced/packed 节奏。日期为本地 YYYY-MM-DD，包含首尾；day_plan 日期相同，trip_plan 多日。国庆等名称须确认年份和日期，不能假定法定假期。

Itinerary 包含时区、Days 与估计总费用；PlanDay 有本地日期与 Items。PlanItem 有 ItemID、Kind、NoteID、Title、Location、Window、估计费用和 Unknowns。note 项引用候选，break/transfer 不指定 NoteID，不能借此虚构商户。

未来规划校验包括日期时区有效、时间窗口有序且不冲突、费用按全程汇总、转场休息合理、全部参与人约束满足。未知交通票价和营业信息不能视为已验证；跨夜、多时区、每天窗口、住宿与实时信息另行细化。ItemID 为后续局部替换预留，本期反馈仍只针对整体 Option。

## 7 历史与短期状态

Decision 保存输入、参与人 ID、候选事实、Result 和反馈，不默认保存完整 Context 或所有私人记忆。嵌套 map/slice 需复制成快照；数据库映射、保留期限和授权撤回时的历史访问规则尚未实现。

Session 保存当前条件、已推荐/排除 ID 与过期时间，绑定身份、空间和任务；切换后不复用，换批生成新的 Decision。规划日期或条件变化时重新组装上下文。未来规划还需已看方案摘要，不能仅排除全部使用过的 Note。

业务类型首轮不额外补 Note/Memory 时间字段；已有 Decision/Feedback.CreatedAt 和 Session.ExpiresAt 保留。实现列表、时效和存储时再补必要时间字段，UpdatedAt 不代替并发 Version。

## 8 待实现的校验和待定规则

首轮校验：实际空间成员与合法收藏；仅 select、无 Planning；最多三个 Option，Selection/Itinerary 互斥且任务一致；NoteID 不重复且来自候选；选项 ID 唯一；参与人匹配合法；未知信息和硬约束处理；反馈归属、幂等及 Session 过期。

V1-01 还需定稿：成员角色、正文删除和访问权限、记忆共享、反馈改选排除、空间配额、记录保留及解除绑定。类型源码位于 internal/notes、memory、space、decisions；当前只完成编译与静态检查，未完成这些行为验证。
