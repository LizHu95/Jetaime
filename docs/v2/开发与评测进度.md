| 问题 | 处理方式 | 当前结论 |

| 核对过度过滤未来计划 | 明确没有完成证据的明确计划仍可保留 | v4复测保留对应未来安排 |
| 问答遗漏一个已提供的链接 | 问答逻辑尚未修改 | 仍存在，列入后续修复 |
| 参考规则未覆盖具体状态误判 | 当前断言主要检查执行、状态、数量和来源；部分案例没有精确行动断言 | 优化试验暴露缺口，需要加强语义与行动状态检查 |
| 未来行动仍可能被判不确定而过滤 | 缓存验证中沿用v4完整判断仍出现该现象；不确定结果不缓存、继续重算 | 模型判断质量仍有波动，不能仅凭早期三次一致认定稳定 |

固定片段中的改善不能推导为全量聊天或新数据上的可靠性。当前未加入混合搜索：已有原文仍判断错误时，先修理解和提取；检索能力需要单独评测。

## 5. 耗时优化进度

二次核对改善了已知错误，但提取平均输入加输出Token由约833增至1684，平均总耗时由约3.34秒增至10.07秒；有候选的两个案例约21–33秒。前者是每例一次的初始基线，后者来自每例三次的v4复测。

2026-10-12围绕第二次调用进行两轮单项输出优化试验：

| 方案 | 具体改动 | 6条案例平均总耗时 | 质量与决定 |
| --- | --- | --- | --- |
| v4基线 | 保留不限长度的必填`reason` | 10.07秒 | 当前使用 |
| v5 | 删除`reason`，同步提示词、Schema和字段校验；只返回候选编号、状态、依据ID | 4.26秒 | 将一项行动完成证据误用于另一项行动，未启用 |
| v6 | 恢复`reason`，提示词、Schema和代码限制最多24个字符 | 4.32秒 | 一个未来行动三次只保留一次，其余判不确定，未启用 |

两个试验均在6条已审核案例上各跑3次。18次执行、引用格式和已配置参考规则检查均通过，但实际状态判断出现问题；规则通过不能替代语义检查。

当前已保留v4。结果说明解释文字可能参与模型判断，不能视为纯展示字段直接删除。缓存、冷启动和机器负载未控制，耗时变化不能全部归因于输出压缩。

### 已完成探索、暂不接入：v7状态核对缓存

探索代码保留v4完整提示词、Schema、reason和状态校验，仅缓存第二次核对的合法结果。常规启动和Phoenix评测均不使用缓存，也不查询缓存所需模型指纹；代码、测试和验证报告保留。只有独立验证脚本显式开启实验开关。缓存键包括完整授权上下文、候选业务内容、模型endpoint/digest、提示词、Schema和调用选项；只去除随机生成的候选ID。命中后重新校验来源和覆盖范围，建议继续使用本轮ID。

内存最多64条、10分钟有效期，重启清空。消息、任务、成员/身份、候选、来源、模型或配置变化使缓存miss。失败、非法或含uncertain的核对结果不缓存；模型指纹不可用时继续完整核对。

6条案例在独立服务中各请求3次：健身案例miss/hit/hit，首次约14.9秒、两次命中各约6.5秒，输出一致；面包片段首次完整核对将骑回家判uncertain，三次继续重算，未缓存不确定判断。验证证明缓存复用行为，不能作为完整语义质量通过率。race、vet及单元测试已通过，当时已验证启用行为，随后按用户决定默认关闭，消息与任务状态保持不变。

暂不接入的原因是：精确缓存只对重复输入有效，日常聊天持续变化时的真实命中率和整体收益尚未验证。当前每次有候选仍完整调用第二次LLM，不以缓存命中测试作为产品交互提速的证明。

后台处理和进度展示仍未实现。缓存只减少重复核对；内容变化或没有可缓存结果时不保证提速。常规Phoenix实验每次使用新Workflow，缓存性能需由同进程专用脚本验证。

## 6. 数据、运行与追溯

私有输入与持续状态位于 `local/data/`：聊天转录、调试状态/日志、评测工作稿、冻结版本和 Phoenix 数据库。包含真实参考的初稿生成器也保留于此。生成的实验输出与源码快照位于 `outputs/evals/`，报告位于 `outputs/evals/reports/`，链路检查结果位于 `outputs/agent-check/`。`local/` 与 `outputs/` 整体被 Git 忽略，`deploy/` 只保存部署定义。目录迁移已校验文件哈希，规则见 [目录约定](../目录约定.md)。

2026-10-14 已清理本地和远端分支中可达的敏感聊天历史；仓库外的原始 Git 备份仍含旧数据。历史评测快照的内容与元数据未因目录整理而改写。

常用入口：

```sh
make assistant     # 调试台 http://127.0.0.1:8081
make eval-check    # 离线校验当前案例
make eval-test     # 评估器单元测试
```

固定已审核提取集运行示例：

```sh
make eval EVAL_ARGS='--cases local/data/evals/versions/chat-v1.1-extract6-reviewed-r2/cases.json --suite-version chat-v1.1-extract6-reviewed-r2 --timeout 300 --context-tokens 16384 --repetitions 3'
```

该命令会调用真实模型并创建新的Phoenix实验。未指定`--judge-model`时语义模型评分仍跳过，即使参考已审核，也不自动产生语义通过率。

早期实验没有保存完整当时源码，只能追溯源码哈希、原模型请求、输入、输出及配置；后续实验已自动保存源码快照。历史文件中的旧路径保留原值，迁移清单记录新位置，避免修改冻结文件破坏哈希。
