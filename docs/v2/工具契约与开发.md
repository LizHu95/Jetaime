# 工具契约与开发

## 入口和职责

新增工具使用 `internal/ai/tools.NewTyped`，声明输入、输出 Go 类型以及处理函数。`Tool` 接口由通用包装器实现，能力包可嵌入 `*tools.Typed[Input, Output]`，增加上下文注入等后端方法。

- `tools/registry.go`：统一目录、注册、名称路由与后端执行 Scope。
- `tools/typed.go`：Schema 推导、编译、运行时校验、超时、错误分类与调用记录。
- `tools/<能力>/contract.go`：输入输出类型、字段约束与结果展示适配。
- `tools/<能力>/tool.go`：能力实现；写业务调用领域 Service。
- `agent/main`：有限工具循环、参数修正、最终回答与 `ai.Run` 执行记录。
- `ai/bootstrap`：只接收已创建的注册表并组装 Agent/运行时，不导入具体能力包，不添加默认工具。

正式群聊在 `app/modules.go` 用一个显式列表注册 `answer_question` 和 `set_reminder`；`extract_todos` 已适配统一契约，但继续保持不在默认注册表中。工具目录包括 `name`、`description`、`inputSchema`、`outputSchema`、只读和幂等提示，命名参考 MCP；当前仍为进程内调用，没有增加 MCP 网络服务。

各入口自行创建注册表并调用 `bootstrap.New(model, name, tokens, registry)`。正式群聊与本地调试台的完整清单分别集中在 `app/modules.go` 对应分支；调试台只注册使用本地上下文的 `answer_question`。隔离评测在 `cmd/workflow-eval/main.go` 显式注册只读问答。测试同样必须明确提供工具，不再有默认工具与 extra 合并的隐藏行为。注册表缺失时启动报错。

## 最小实现

以下示意的处理函数可直接传入 `NewTyped`。若需要依赖注入，用结构体方法或闭包提供领域 Service。

```go
type LookupInput struct {
    Query string `json:"query" jsonschema:"需要查询的内容"`
}

type LookupOutput struct {
    Text string `json:"text"`
}

func lookup(ctx context.Context, scope tools.Scope, in LookupInput) (LookupOutput, error) {
    // 用 scope.Context 中后端提供的身份和群组调用业务 Service。
    return LookupOutput{Text: "查询结果"}, nil
}

tool := tools.NewTyped(tools.Metadata{
    Name:        "lookup",
    Description: "查询信息",
    ReadOnly:    true,
    Idempotent:  true,
}, lookup, tools.Options[LookupOutput]{
    Input: func(s *jsonschema.Schema) {
        s.Properties["query"].MinLength = jsonschema.Ptr(1)
    },
})

registry, err := tools.New(tool) // 应在启动时检查错误。
```

Schema 使用固定版本 `github.com/google/jsonschema-go` 从类型生成。JSON 字段名、类型、嵌套结构、必填项和未知字段限制由结构体生成；`jsonschema` 标签提供字段描述。`omitempty` / `omitzero` 表示可省略，指针和切片默认可为空；要求数组非 null 时应显式收紧 Schema。`Options.Input` / `Output` 补充枚举、格式模式、长度和数值范围等约束；需要检查实际日期、证据归属和权限等语义时，在业务处理函数或领域 Service 校验。

`Registry.New` 在启动时拒绝名称重复、无效名称、空处理器、不可推导的类型或无法编译的 Schema。输入和输出根类型都必须是对象。注册后不要修改工具配置；`Definitions()` 返回 Schema 的副本。

## 执行与身份

执行流程为：检查取消/超时 → 校验后端上下文 → 输入 Schema 校验 → 解码为强类型输入 → 执行业务函数 → 检查执行上下文 → 输出编码及 Schema 校验 → 展示适配。

`Scope` 由后端传入，不进入模型参数：其中包含认证用户、群组、原始上下文、消息截止 seq 及按需加载器。业务权限和提醒操作的幂等 Guard 仍由领域与 chat 层负责。Schema 本身不授予权限；只读/幂等提示也不替代实际权限和事务保证。

成功的输出在工具内部保持强类型；混合注册表边界使用已经过校验的 `json.RawMessage`。`Options.Present` 可将成功结果映射成 `Completion`，`Metadata.Terminal` 由后端决定是否结束循环；工具不返回或覆盖 `ai.Run`。主 Agent 组装最终记录并沿用既有 HTTP/数据库回答格式。

工具内部若包含额外模型或检索步骤，可调用 `RecordStep` / `RecordModelIdentity` 补充诊断。外层执行器统一记录起止时间、耗时和错误，主 Agent 的 `tool_call` / `tool_result` 保存调用参数、已校验结果与执行失败。Langfuse 输入输出内容沿用 `JETAIME_TRACE_CAPTURE_CONTENT=true` 的显式开关和长度限制；默认不导出聊天正文或完整参数。

## 结果与错误

- **缺少用户信息**：返回有效业务结果，例如提醒 `needs_clarification` 和 `missingFields`，由展示适配生成追问。
- **可修正的模型参数**：返回 `tools.InvalidArguments(code, message)`。校验反馈作为数据交回主 Agent，模型可以按原文和 Schema 修正；整个循环最多 3 步。此类错误必须在有副作用的操作之前返回，或由领域事务确认已经回滚。
- **基础设施失败、取消或超时**：返回普通 Go error，不自动重新执行工具。
- **输出违反契约**：返回 `tools.ErrInvalidOutput`，不发布数据或最终回答，也不自动重放可能已提交的写操作。

不要把错误参数静默改成空值。提醒工具缺少时间证据会返回 `time_evidence_missing`，模型可补上正确来源再调用；只有用户确实未提供时刻时，才传空字符串并生成待补充草稿。日期、标题等领域校验失败在事务回滚后可反馈为 `invalid_reminder`；版本冲突和权限失败继续沿用原有错误路径。

## 验证

通用契约测试在 `tools/typed_test.go`，覆盖必填字段、额外字段、枚举/边界、无效输出、无效注册、超时和取消。主 Agent 的 `tool_contract_test.go` 验证有限修正、不执行错误参数、保存诊断以及不重放写操作。能力包继续覆盖来源、授权和业务语义。

普通 Go 测试不会调用真实模型。设置 `JETAIME_TEST_MODEL_CONFIG` 为模型配置路径并提供该 profile 对应的密钥后，可显式运行提醒的 `TestReminderHistoryLive`；它使用模拟提醒存储，不写入真实提醒或聊天。PostgreSQL 集成测试仍需单独配置 `JETAIME_TEST_DATABASE_URL`，默认跳过。
