# iOS 最简版本设计草案

更新：2026-10-14。状态：双人会话、退出规则、AI 触发与数据库选型已确认；其余交互为设计建议，尚未实现。

## 已确认范围

- 将现有 Web 产品延伸为可在个人 iPhone 上安装测试的 iOS App。
- 底部只有两个 Tab：聊天、我。
- 聊天采用熟悉的微信式列表与聊天交互，群目前固定两位真人，产品体验相当于加好友后聊天。
- 每个群只有一个共享 AI，作为两个人的共同助手；AI 归属于群组，不归属于个人。
- 会话成立后不可邀请或新增成员。任一人退出后，会话结束，对双方均不再提供该会话。
- 首版通过 @AI 显式触发，静默监听作为后续探索。
- 后端主数据库采用 PostgreSQL。

## 首版体验

建议流程：登录 → 找到对方账号并发送添加请求 → 对方接受 → 原子创建两人成员关系、会话和共享 AI → 双方聊天 → @AI 获得共同助手的回答。

添加请求与接受流程为设计建议。请求接受前不创建可聊天的单人群；拒绝或取消请求不生成会话。注册邀请码只控制内测注册，不作为会话入群机制。

每个群的 AI 使用该群聊天作为上下文，帮助双方找回约定、回答问题，并逐步接入待办协同。不同群的消息和 AI 上下文隔离。

## 页面与入口

| 页面 | 内容 | 主要操作 |
| --- | --- | --- |
| 聊天 Tab | 对方头像、昵称、最后一条消息、时间、未读数；按最新消息排序 | 点击进入会话；右上角“＋”添加对方，处理收到的添加请求 |
| 群聊 | 顶部群名和真实成员人数；消息流；底部文字输入框和 @AI 按钮 | 发送文字、@AI、点击引用定位原话、右上角进入群详情 |
| 群详情 | 两位成员、一个共享 AI 的说明 | 退出并结束会话；操作前明确说明双方均失去该会话 |
| 我 Tab | 头像、昵称、账号；我的待办入口；退出登录 | 修改昵称、查看本人待办 |

群聊和群详情作为下一级页面打开，隐藏底部 Tab；返回聊天列表后恢复。添加对方、编辑昵称采用表单弹层。未登录时先展示登录/注册页面，复用 Web 账号。

共享 AI 的说明放在群详情中。“我的待办”汇总各群中本人负责的事项，作为后续接入现有协同能力的入口，首轮聊天验证可后置；没有接入时不展示可点击的空功能。

## 群聊视觉

- 浅灰背景；本人消息右侧、绿色气泡；他人和 AI 消息左侧、白色气泡。
- 群消息显示头像和发送者昵称，AI 显示固定名称“AI 助手”和 AI 标识。
- 群头部人数只计真人；详情明确显示“2 位成员 · 1 个 AI 助手”，避免混淆。
- AI 回答作为普通可阅读消息出现；生成中显示状态，失败时提供重试。
- 引用置于回复下方，点击定位到当前群的原消息。

## AI 规则

1. 会话成立时关联一个共享 AI，固定两位真人成员，不提供新增成员入口。
2. 首版双方都通过 @AI 或输入框旁的 @AI 按钮提问，普通消息只保存和同步，不触发模型调用。静默监听后续设计。
3. 双方调用同一个群助手，AI 回复在群内对双方可见。
4. AI 仅使用当前群中调用者可见的消息；不读取其他群和成员私人信息，不自动代表任一成员作出承诺。提取的待办经成员确认后保存。
5. 双方从会话成立起参与，拥有相同的会话历史可见范围；不存在新成员历史授权规则。
6. 任一成员退出就关闭整个会话：双方列表移除、历史读写拒绝、共享 AI 停用。排队的 Agent 调用取消；已在执行的调用尽力停止，返回结果不得写入已关闭会话。
7. 建议用关闭状态立即落实产品上的消失，不直接把退出等同于物理删除数据库记录。历史、调用记录及待办的保留或删除策略另行确定；已关闭会话不再向成员或 Agent 提供上下文。

## 实体与存储调整

- 保留 User、UserCredential、AuthSession、Group、GroupMember、Message、GroupAssistant、AgentRun。
- Group 固定双人；建议记录规范化的两位用户 ID，在活跃状态下对用户对建立唯一约束，防止重复会话。禁止添加自己。关闭后重新添加创建新会话，不复活旧历史。此重复会话策略为建议。
- GroupMember 保留用于权限和 last_read_seq；成员集合建立后不可变，不需要群主踢人或成员邀请权限。
- 移除 GroupInvite，建议改用 ContactRequest：from_user_id、to_user_id、status、created_at、resolved_at、group_id。双方可以对称操作，创建者不拥有额外群管理权限。
- PostgreSQL 事务保证接受请求时同时建立两位成员、一个群和一个助手；关闭会话与消息/AI 回复写入采用共同的并发锁定规则，防止关闭后继续写入。
- PostgreSQL 持久化登录会话；模型调用放在数据库事务之外。Task 在待办能力接入时补充。

表结构、数据库约束与事务流程已整理到 [PostgreSQL 数据设计](PostgreSQL数据设计.md)，附空库建表与验证 SQL。API 已提供可选 PostgreSQL 连接、版本迁移及就绪检查；业务接口仍待接入。

## 首版范围与验收

第一阶段只跑通账号、添加对方及接受、固定双人会话、文字消息保存与同步、未读数、共享 AI 问答，以及最小个人资料。语音、图片、完整好友通讯录、朋友圈、支付、独立日历和系统推送后置。

使用两个测试账号验证：接受添加请求后原子建立双人会话及唯一助手；第三人不能加入；消息同步且重启后保留；双方均可 @AI 且看到其回复；普通消息不触发模型；其他群消息不会出现在回答中；任一人退出后双方均不能继续读写，进行中的 AI 结果不能落入该会话；发送失败可重试且不重复产生消息。未读数仅统计上次阅读后来自其他发送者的消息，进入群并看到消息后清零。

## 与当前实现的关系

旧 Webchat 实现已移除。Assistant 调试台具有群组历史问答、来源与待办确认能力，但使用模拟身份、限本机访问。移动 Web 原型使用模拟 AI 和浏览器本地状态。

后续开发需补齐 PostgreSQL 存储、添加请求、真实双人会话及成员权限、按群消息与同步，再将 AI Workflow 接入受认证的群聊接口。客户端可以复用服务端能力，但仅封装现有页面不足以实现本草案。原生客户端或 Web 容器的实现选择留到交互确认后决定。
