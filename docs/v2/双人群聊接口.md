# 双人群聊、实时同步与共享 AI

更新：2026-10-14。普通文字消息、共享 AI 完整回复、阅读进度、实时推送和断线补拉已接入真实 PostgreSQL。复用基线消息、阅读进度和 AI 任务表；Agent 结果元数据由迁移 000003 添加。消息不可编辑或删除。

## 启动与页面

`make dev` 默认开启 Auth、好友群组、聊天 HTTP、WebSocket 和共享 AI worker，需要有效模型配置。共享 AI 使用 local/models.json 的默认 profile，也可用 `-model-profile` 或原有模型参数覆盖；启动参数固定模型，切换需要重启。显式用 `-chat-ai=false` 关闭 AI 时，@AI 提问仍保存，任务显示 ai_unavailable，不生成假回答。共享 AI 随认证模块启动；显式传 `-chat-ai` 必须同时启用 `-auth`，并提供有效模型配置和对应密钥环境变量。

Web 页面 `/page/chat/` 为群列表，`/page/chat/{groupId}/` 为聊天页；登录成功页和好友群组页均提供入口。前端包含文字发送、同一消息 ID 的失败重试、历史分页、未读角标、定位首条未读、@AI 按钮/文字提问、排队/处理中/失败状态、AI 重试及关闭群聊。桌面双栏、手机单栏。

## HTTP 接口

以下接口均验证 Bearer Token，并从会话确定本人；每次查询或写入要求群为 active 且本人是成员。其他人和关闭群返回 `404 group_not_found`，不会泄露群消息。缺失/过期/撤销 Token 返回 `401 unauthorized`。

路径前缀为 `/api/chat/groups/{groupId}`：

| 方法与后缀 | 输入 | 返回 |
| --- | --- | --- |
| GET（无后缀） | 无 | `{id,members,lastSeq,readSeq,unreadCount,assistantName,aiEnabled}` |
| GET /messages | afterSeq（默认 0），或 beforeSeq；limit 默认/最大 100 | `{messages,hasMore}`，消息始终按 seq 升序 |
| POST /messages | `{content,clientMessageId,mentionsAI?}` | 已保存的消息；重复发送相同内容返回原消息 |
| POST /read | `{seq}` | `{readSeq}`，新的本人阅读进度 |
| GET /runs | 无 | 最新 100 个本群 AI 任务及状态 |
| POST /runs/{runId}/retry | 无需请求体，仅原提问人 | 重试原 failed 任务；重复请求不创建新任务 |
| POST /close | 无需请求体，任一成员 | 逻辑关闭群、停用助手、取消 queued/running 任务 |

消息结构：`{id,groupId,seq,senderType,senderId,senderName,content,mentionsAI,clientMessageId,replyToId,createdAt}`。AI 的 senderType 为 assistant、senderId 为 null，replyToId 指向提问，clientMessageId 为 null。AI 任务包含 id、triggerMessageId、requestedBy、contextEndSeq、status、attempt、errorCode、responseMessageId。

文字消息最多 4000 个 Unicode 字符，不允许全空白或空字符；请求体最多 32 KiB，须为 application/json，拒绝未知字段。clientMessageId 是标准 UUID。相同发送人 + clientMessageId 只能对应同一群、内容和 AI 触发状态，复用为不同消息返回 `409 message_conflict`。保存时锁定群行，分配连续 seq，插入消息和可选 AI 任务后一起提交。未成功事务不消耗序号。

## 阅读进度与未读

每位成员只维护一个 last_read_seq。服务端取新旧进度最大值，并限制不超过群内 last_message_seq。未读为 `seq > last_read_seq` 且 sender_user_id 不是本人的消息数量；AI 消息对双方都计入。

客户端只在页面可见、有焦点、消息尾部实际处于聊天可视区域时上报进度。打开列表、后台标签、仅收到实时通知都不会清除未读。初次打开群定位第一条未读；读取进度通知只推送给本人的在线设备，其他成员的已读状态本期不展示。

## 实时协议

`GET /api/chat/events` 升级为 WebSocket，验证同源 Origin。浏览器连接后 5 秒内发送第一帧：`{"type":"authenticate","token":"Bearer 原始 Token"}`；成功返回 `{"type":"ready"}`。Token 不放 URL 或 subprotocol。认证失败以 1008 关闭，临时认证服务错误以 1013 关闭并允许重连。

事件为 `{type,groupId?,actorId?}`，type 包括 message、read、ai、group_closed、resync。事件仅是更新提示，不携带聊天内容或凭据。HTTP 事务内 pg_notify 在提交后生效；每个 API 实例用独立 PostgreSQL LISTEN 连接接收通知，按群成员分发。read 仅分发到阅读人的设备；关闭通知发给双方。慢客户端收到 resync，队列有界。

连接每 15 秒 ping；每 2 秒及每次发送通知前重新校验数据库会话，退出、改密和过期使旧连接关闭。客户端指数退避重连，ready/resync 后重查群列表、阅读进度、任务，并按最后连续收到的 seq 补拉消息。每 15 秒及重新聚焦也与数据库校对，修复通知丢失；重连、重复通知和 HTTP 重试按消息 ID 去重并按 seq 排序。应用关闭时没有系统推送。

## AI 队列与回复

普通消息不触发模型；@AI 按钮设置 mentionsAI，或正文包含独立 @AI 标记后触发。提问与唯一 queued 任务在同一事务保存。两个 worker 可处理不同群，同一群最多一个有效 running 租约，按提问 seq 排队。每次领取增加 attempt_count，并设定模型超时 + 30 秒租约。过期任务恢复后仍使用同一个任务 ID；晚到结果按 attempt_count 和租约进行隔离。

上下文只取本群 `seq <= context_end_seq` 的消息，不含未来对话、其他群或单独私有资料。2026-10-19 起，群聊 qa 使用近期完整消息窗口：倒序最多读取 201 条，以额外一条判断是否省略历史，从最近 200 条中按完整请求的保守字节预算选择连续后缀，再恢复时间顺序。预算包括系统规则、Schema、JSON 转义与元数据、问题、2048 输出预留和 512 协议余量；保留当前触发消息，不截断单条正文。当前提问及必要元数据本身放不下时仍失败 context_too_large。

输入及持久化 agent_result 增加 historyScope（policy=recent-messages-v1、earlierMessagesOmitted），群聊 QA Prompt 版本为 qa-v4-evidence-boundaries-recent-v1。省略更早记录时，系统规则要求模型不得声称检查全部历史，回复正文附加“本次仅参考近期聊天，未检索更早记录。”来源 ID 仍只能来自本次选中的原文。完整历史保留在数据库；旧 failed 任务重试仍固定在原 context_end_seq，但使用新窗口策略。当前未实现更早历史检索或摘要。

待办 extract 及本地 Workflow 调试台继续使用完整快照，超出预算明确失败，避免仅凭近期窗口遗漏早期承诺或后续取消。原 Agent 通过现有 Eino 适配器调用启动选定的 Ollama/OpenAI 兼容模型，使用原 QA/提取 Schema 并校验来源。失败、空内容、非法 JSON/字段/空字符不会保存为回答，仅更新任务失败状态并推送。

所有推理请求均执行本地容量保险：QA、提取、接受核对、行动核对在调用前检查，统一模型适配器在任何模型 HTTP 请求之前再次检查。预算包含全部消息与角色、单独传递的 Schema（即使提示词中已有一份）、每条消息的协议开销、512 余量及请求的输出预留；容量取启动配置与请求 num_ctx 的较小值。容量或输出预留缺失、或预算超限时返回可识别的容量错误，群聊归类为 context_too_large，不调用模型，也不自动重试。此检查仍为保守 UTF-8 字节估算，并非模型专用 tokenizer 的精确计数。

完整回答保存为一条 assistant 消息，分配同一群消息序号，关联提问，更新任务 succeeded，并在提交后向双方通知。同一任务最多保存一个回答；AI 排队/处理中/失败状态不算未读。用户离线不取消任务；关闭群时取消队列及运行状态，晚到模型输出不能落库。原提问人可重试失败任务，提问消息和任务不重复创建。

## 原 Agent 接入与本地 Ollama（2026-10-14）

发送消息的 AI worker 已改为调用 `assistant.Agent`，与原 Workflow 调试台复用同一个执行引擎。历史问答使用既有 qa-v4 提示词、证据层级、answered/insufficient_evidence/conflicting_evidence 状态和来源 ID 校验；待办提取使用既有 extract-v19、行动证据边界和独立状态核对。每次调用接收经过成员鉴权、本群且截至提问 seq 的独立数据库快照，不共享本地 JSON Store 或其他群历史；普通消息不调用 Agent。

2026-10-19 起，前端移除能力下拉框，@AI 按钮或正文 @AI 均自动进入主 Agent。POST /messages 不传 agentKind 时，AI 请求保存为 auto，普通消息仍为 qa 且不调用模型。当前主 Agent 为 main-v1：默认在一次模型调用中直接回答、给出建议或澄清，不先分类到 help/qa 子 Agent。只有明确的待办提取请求才委派 extract 子 Agent。主 Agent 使用下述默认上下文，预留 2048 输出，容量取启动模型配置。尚未接入历史检索工具、历史问答 skill 或日常问答 skill；历史问题只依据本次原文，证据不足明确说明，不声称查过完整历史。

默认上下文通过 `assistant.ContextInjector` 函数注入。输入 `ContextRequest` 包含授权快照、当前消息 ID、问题、直接关联原文、执行时间及容量。默认实现 `assistant.InjectDefaultContext` 保留完整当前消息与关联原文，注入群成员及 request.messageId / senderId / sentAt / currentTime / timezone（Asia/Shanghai），再选择最多 12 条近期背景消息。背景按每条原文序列化后的字节数计算，总计不超过 4 KiB；当前请求与直接引用单独计入完整请求预算，不占这 4 KiB。原文去重并保留顺序，即使发送时间相同也不反转。默认不附带全部待办、摘要或长期记忆，historyScope.policy 为 default-context-v1。系统规则、可用能力和 Schema 由固定模型请求模板加载，不从聊天正文提取。

Service 构造函数可通过 `chat.WithDefaultContextInjector(fn)` 替换或包装默认函数，现有调用方无需修改。注入后的必需消息检查、群组/发送者校验、数据库 seq 截止边界及最终容量保险独立于自定义函数执行。直接关联原文通过已有 reply_to_id 关系读取，仍限定本群且 seq 不晚于原提问；本次不增加回复消息的前端入口。必需原文自身放不下时直接失败，不截断或静默丢弃。预算使用真实 main-v1 请求模板及 2048 输出预留。`assistant.WithMainInstructions(fn)` 或 Service 的 `chat.WithMainInstructions(fn)` 可注入附加任务规则，作为下一步 skill 指令扩展入口；加载附加规则后会再次检查预算。该入口本身不安装 skill、不提供历史检索，也不授予外部动作能力。

主 Agent 返回受 Schema 约束的 action=answer/extract、basis=general/history/mixed/none 及可空 answer。普通回答保存为 agent_kind=main，basis 记录答案依据；history/mixed 的 answered/conflicting_evidence 必须有合法来源。extract 决策必须 answer=null、basis=none，不允许主 Agent 伪造子 Agent 结果。未知动作、非法 JSON、无效字段或来源失败 invalid_model_response，不调用子 Agent。每次最多委派一次，无自主循环。主 Agent 与子 Agent 共用启动模型、调用超时和容量保险；Trace 包含 assistant.main / assistant.child.extract，普通回答没有子 Agent 调用。agent_result.route 保存 main/extract 及 main-v1，原队列任务保持 auto。重试仍固定在原触发 seq。新版 API 启动前需应用迁移 000007，扩展 main 结果类型。

待办子 Agent 的范围是只读的“从指定群聊证据中提取并核对行动建议”。输入为原始提取请求、授权群组快照、来源 ID、成员和已有任务状态；提取请求中的人员/时间/消息范围应约束候选，后续消息用于核对完成、取消及修改，不扩大提取范围。当前仍由服务端加载截至原提问的完整快照，超限直接拒绝；以后可由历史检索工具提供更精确的证据范围。输出为带原始来源的候选标题、负责人、时间表达和去重信息，复用独立状态核对。它不创建任务、不设置提醒、不修改任务状态，也不执行行动；这些写操作应由独立工具及用户确认承接。范围有关键歧义时主 Agent 先澄清。Prompt 版本为 extract-v20-scope-bounded。

显式 agentKind=qa/extract/help 及 @AI /extract 命令为已有调用方保留，前端不再发送手选能力。`@AI预算是多少` 这样的中文紧邻写法可触发，`@AIR` 不触发。提取结果只是建议，显示“尚未创建”，不会自动写入规划或创建任务。当前历史 QA 仍使用近期窗口，尚未实现更早历史检索；自动路由不改变该限制。

自动路由验证（2026-10-19）：独立临时 PostgreSQL 的 race 集成测试覆盖三个子 Agent、上下文截至原提问、结果与路由版本持久化、非法路由失败及同任务重试。浏览器联调使用受控模型，桌面/手机共 47 项通过、3 项按平台条件跳过，验证按钮 @AI 自动提取及直接输入 @AI 自动求助。配置的真实云模型另外通过 6 条路由样例（日常建议、周末建议、历史安排、历史发言、提取待办、请求设置提醒）和除味问题的日常回答链路；固定样例结果不代表所有意图的路由准确率。真实模型测试为显式 opt-in：设置 JETAIME_ROUTER_MODEL_CONFIG 为模型配置文件，JETAIME_ROUTER_MODEL_PROFILE 指定 profile（默认 cloud-qwen），执行 go test -count=1 -run '^TestRealModelRouterIntents$' ./internal/assistant，密钥从相应环境变量读取。
