# 历史向量化与增量记忆（M1）

本阶段实现历史片段检索、结构化记忆、增量处理和最小内部检索方法。主 Agent 暂未接入这些查询，也不引入 Tool Loop、Rerank、提醒或主动介入。

## 处理链路

```text
PostgreSQL 原始消息（群内 seq）
  → 发现群并记录首次回填水位
  → 租约抢占一个群的消息批次 + 最多 3 条旧消息作上下文
  → LLM 提取候选 → 持久化候选检查点
  → 候选 Embedding（内容哈希缓存）
  → 按人物/类型/事件/时间范围过滤，向量召回相关旧记忆
  → 完全重复直接 NOOP；其他相关项交给 LLM 消解
  → 事务写入历史片段、记忆版本、来源、向量任务并推进游标
  → 独立 Embedding Worker 处理持久队列
```

历史片段按时间邻近（20 分钟）、最多 12 条和约 4500 字节拆分；单条较长消息保持完整。每批最多读取 43 条原始消息，文本预算 18000 字节；优先丢弃可选 overlap，避免长消息阻塞。AI 消息只推进水位，不作为人类事实索引。原始消息只有 user/assistant 两种，无额外系统消息。

首次记录 `backfill_end_seq`，水位之前无需等待阈值。追上后任意条件满足即处理：15 条未处理用户消息、聊天空闲 5 分钟、最早未处理消息等待 30 分钟。5 秒扫描一次，最多每分钟发现新群并补偿扫描向量队列。

## 数据和恢复保证

新增迁移：`000008_memory.up.sql`，不修改已有迁移，不重建数据库。

| 表 | 持久状态 |
| --- | --- |
| `memory_progress` | 每群独立 seq 游标、首次回填水位、pipeline 指纹、租约令牌、失败重试 |
| `memory_batches` | 已完成提取的候选、逐个消解结果检查点，以及批次是否提交 |
| `memory_documents` | 历史片段、记忆逻辑 ID、修订版本、当前状态、时间范围 |
| `memory_document_sources` | 同群原始消息外键、可回查的证据关系 |
| `memory_embeddings` | 模型版本、维度、内容哈希、pgvector 向量、任务与重试状态 |

- **部署/重启不重置游标、不重算 ready 向量。** 无新消息时不调用提取模型。
- 提取完成并保存检查点后，中断重启复用候选；逐个消解结果也保存检查点，重启跳过已经完成的候选；向量完成并保存后，复用向量。
- 候选文本直接成为正式记忆时复用同一向量；消解后文本改变才排队生成新的向量。
- 批次的历史片段、记忆修改、任务入队和游标在一个事务中提交，失败全部回滚。空候选也推进游标并建立历史片段索引。
- 每群同一时间只有一个有效批次租约（5 分钟，单次处理最长 4 分钟）；过期 Worker 不能提交。Embedding 任务单独使用 2 分钟租约和 60 秒 HTTP 超时。
- 失败保留任务，按次数退避（30 秒至 10 分钟），处理状态持久化错误；不会因失败跳过消息。
- **外部模型调用无法承诺严格一次。** 模型已返回、尚未保存时崩溃，恢复后可能再次调用；已成功保存的步骤不重复处理。
- `-memory-backfill` 跳过触发阈值，但仍遵守游标、检查点和租约，是“继续回填”，不是“清空重建”。存在租用中/等待重试的数据时退出报错，可稍后重跑。
- 模型、模型修订、向量维度、提取模型身份或 pipeline 版本变更时，已有 pipeline 不匹配会拒绝启动处理。**本阶段不提供自动模型升级/重建命令**；升级须另行设计版本化回填和切换，不能删游标来解决。

## 记忆与权限边界

- 本期仅从当前双人群聊天提取**群共享记忆**；subject 表示记忆涉及的人物或 shared，不表示私人可见性。未接入私人聊天或跨群用户画像。
- 类型包括 preference / decision / plan / fact / constraint / event。记录 enduring / temporary / event 时间范围与具体事项标识。
- ADD 新增；NOOP 只补证据；UPDATE 留下旧版并建立新版；INVALIDATE 留下取消记录并停用旧版。
- 修改和取消必须显式变更，且旧记忆人物、类型、事项标识、时间范围完全匹配；相似度不能直接覆盖。
- 同批次同一身份/事项只允许一个最终候选，来源至少包含一条新消息；旧消息 overlap 不能单独产生重复候选。来源归属由应用校验、同群外键兜底。模型语义判断仍需真实案例评测。
- 每条检索 SQL 均校验群成员与群状态；向量查询先鉴权再调用外部模型，返回前再次鉴权。
- 现有产品关闭群而不支持成员退出；关闭群事务清理所有派生记忆、检查点和向量，原始聊天按现有规则保留。派生写入与关闭串行，旧 Worker 无法回写。
- 删除原始证据会撤回相关派生版本、对应向量及候选检查点，并使未完成租约失效；不回退已完成游标。其他仍存在的历史不会因此全量重算。消息编辑目前被数据库明确拒绝，后续支持编辑时需提供显式重建流程。

## 模型配置与部署

配置模板：`services/api/config/memory.example.json`。**正式 API 启动时自动启动记忆处理与向量 Worker，没有 enabled 配置开关。** Embedding 为 `qwen3.7-text-embedding-flash`、1024 维，extraction 为 `qwen3.7-plus`；模板的区域 URL 仍占位，需要替换为真实地址。配置或密钥缺失时启动报错，不静默跳过处理，不生成假向量。

1. 复制模板到 `local/memory.json` 并填写真实区域 URL；本项目本地配置已使用现有云模型的连接地址。
2. 数据库主机安装 pgvector；迁移要求扩展位于 `public`，执行迁移的账号需要创建扩展的权限，或 DBA 预先执行 `CREATE EXTENSION vector WITH SCHEMA public`。
3. Embedding 使用 `qwen3.7-text-embedding-flash`，固定为默认 1024 维，运维 revision 初始为 `v1`。启用前填写所在区域的真实 URL 和密钥环境变量，核对输入字节预算。revision 是由运维固定的向量空间版本标识，不是额外发送给 API 的参数；模型本身仍应尽可能固定版本。
4. extraction 使用 `qwen3.7-plus`，与主 Agent 对话模型一致；配置独立，需核对所在区域的真实 URL。当前该模型同时负责候选提取和必要时的记忆消解（ADD / UPDATE / NOOP / INVALIDATE）；没有相关旧记忆或完全重复时，不额外调用消解模型。建议起始上下文 32768；所有 LLM 请求保留输出预算并在调用前校验。`max_input_bytes` 至少为 `18000+2048`，也必须符合实际 Embedding 模型的输入能力。
5. 无需额外开启功能，启动会校验配置与密钥并启动 Worker。旧配置中的 enabled 字段应删除；当前解码器会拒绝未知字段。迁移命令与仅健康检查/本地调试台模式不启动记忆处理。

本地回填（会加载 `local/.env`，需提前迁移）：

```sh
make memory-backfill
```

服务启动可显式指定 `-memory-config /absolute/path/memory.json`，或设置 `JETAIME_MEMORY_CONFIG`。未指定时优先读取工作目录的 `memory.json`，再读取 `../../local/memory.json`，因此本地 `make dev` 自动加载本地记忆配置。

构建要求 `local/memory.json` 存在，自动打包该配置与 `memory.example.json`。服务器 `start.sh` 自动使用旁边的 `memory.json`，环境变量可覆盖路径。

```sh
bash start.sh migrate
bash start.sh memory-backfill  # 可选；常驻 Worker 也会自动继续历史回填
bash start.sh restart
```

`memory-backfill` 不启动 HTTP 或主 Agent，也不需要主 Agent 的模型配置。正常 API 启动已经会自动处理历史与新增消息，手动回填只是立即处理积压数据并退出。部署包不包含数据库或处理状态，部署和重启不重置游标或检查点。

Embedding 使用百炼兼容的 `/embeddings` JSON 接口（float 输出），不固定具体模型；本期不加 Rerank，pgvector 使用精确余弦检索，不提前固定 ANN 索引的维度。

接口依据：[百炼 Embedding 接口](https://help.aliyun.com/zh/model-studio/embedding-interfaces-compatible-with-openai)、[pgvector](https://github.com/pgvector/pgvector)。

## 内部检索契约

memory 不注册 HTTP 路由。后续主 Agent 工具通过 `Service.Search(ctx, groupID, actorID, SearchInput)` 在进程内调用；群组与用户身份由可信调用方传入，内部仍检查成员身份及群状态。

下面是 SearchInput 的字段示意：

```json
{
  "query": "杭州",
  "limit": 5,
  "mode": "hybrid",
  "kind": "decision",
  "subject": "shared",
  "since": "2026-01-01T00:00:00+08:00",
  "until": "2026-12-31T23:59:59+08:00"
}
```

仅 query 必填。limit 默认 5、最多 20。mode 为 hybrid / vector / keyword；kind、subject、since、until 可省略。

- vector 使用配置中的同一向量空间；keyword 使用中文可用的子串匹配，作为 V1 基础实现；hybrid 对两路各 Top20 进行 RRF 排序，不调用 Rerank。
- documents 返回文本、源消息 IDs、涉及人物、类型、时间范围、版本等；按消息查询接口可回查原文。历史片段保留当时发言者身份。
- 同时返回 cursorSeq、recentUnprocessed（游标之后最多最近 30 条用户消息，按时间正序）和 recentOmitted，覆盖尚未处理的新事实，不谎称包含全部近期记录。
- 结构化记忆已提交但向量尚未完成时，关键词查询仍可命中；向量查询需要相应任务完成。正式 API 要求记忆模型配置有效后才能启动。
- score 是 RRF 排序分，不是事实可信度。历史片段可能包含已改变的旧决定，QA 阶段必须根据时间和来源解释，不能把检索结果当正式任务状态。

处理水位、回填水位和失败原因保存在 `memory_progress`，向量积压保存在 `memory_embeddings`，通过数据库与 Trace 排查，不提供专门的状态 HTTP 接口。游标代表片段与记忆事务已提交，不代表所有向量已经完成。

## 验证

使用隔离 PostgreSQL + pgvector 数据库，测试为每个用例创建独立 schema，不读取真实聊天或调用真实模型：

```sh
JETAIME_TEST_DATABASE_URL='postgres://USER:PASSWORD@HOST:PORT/TEST_DB?sslmode=disable' make db-test
```

覆盖重复迁移/服务重建不增加模型调用、只处理新增消息、检查点恢复、过期租约拒绝提交、Embedding 失败与恢复、空候选推进、触发阈值、长消息分批、来源不重复、NOOP 复用向量、偏好与临时状态隔离、修改版本、取消留痕、跨群权限、删除及关闭清理、模型版本变更拒绝混用、占位配置和接口适配。

真实模型尚未实测，因此中文召回 Recall@K/MRR 与语义消解质量尚未实测；接入后应使用脱敏历史案例评估。现有 Trace 增加 memory.process 与 memory.embedding（含 Token 用量）观察点，数据库记录处理水位与积压；完整质量指标由后续评测补齐。
