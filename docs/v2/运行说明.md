# V2 最简 Workflow Demo

更新：2026-10-11。当前是可运行的开发调试台，使用固定群组与模拟身份，不是完整多人聊天产品。

## 启动

先运行本机 Ollama，确保已安装 `qwen3.5:9b`（或替换为已安装模型）。在仓库根目录执行：

```sh
make assistant
# 自定义已安装模型 / 端口：
make assistant ASSISTANT_ARGS='-model qwen3.5:9b -addr 127.0.0.1:8081'
```

浏览器打开 <http://127.0.0.1:8081>。服务只允许监听本地回环 IP。无需前端安装或构建，页面嵌入 Go 程序。停止服务使用 Ctrl+C。

## 调试路径

1. 选择群组、模拟成员与模型。默认加载用户提供的微信记录，2 位成员、441 条消息；两个账号已合并为同一位成员。
2. 点击“历史问答 + 引用”，默认问题为“这段聊天里有哪些明确的行动安排？”。点击来源按钮定位原文。
3. 点击“从当前历史提取待办”。调整标题、负责人、日期后确认创建；忽略建议不会保存任务。
4. 在左侧模拟发送消息，选择只保存、发送后问答或发送后提取。触发策略由页面明确选择，未实现模型自动路由。
5. 查看本人待办并标记完成，也可切换成员、取消“仅我负责”查看本群全部任务。
6. 在右侧展开运行步骤，查看隔离后的上下文、实际请求 / Schema、模型原始响应与校验错误，或下载该次运行 JSON。

消息先保存、后调用模型。模型失败不回滚消息；可以直接重试右侧 Workflow，无需重复发送。

## 文件与参数

路径相对 `services/api`，可通过启动参数改动：

| 文件 | 用途 | 参数 |
| --- | --- | --- |
| `../../local/data/chat-history/history.fixture.json` | 可编辑的用户、群组、成员和原始历史；程序只读 | `-fixture` |
| `../../local/data/assistant/state.json` | 模拟新增消息与已确认任务；原子替换保存 | `-state` |
| `../../local/data/assistant/runs.jsonl` | 每次问答 / 提取的完整运行记录 | `-log` |

修改 fixture 后点击“重新读取历史 JSON”。如果与已保存消息 / 任务冲突，拒绝加载并保留原数据。临时实验可指定新的 `-state` / `-log` 文件；不要同时启动两个进程写同一文件。

其他参数：`-ollama-url`（默认 `http://127.0.0.1:11434`）、`-model-timeout`（默认 `5m`）、`-context-tokens`（默认 `98304`）。三个数据文件必须不同。

## 实现与限制

- 两条确定流程：组装当前群历史 → 专用 Prompt / Schema → 一次模型调用 → 校验结果。未引入 Agent Loop、小模型 Router、摘要、混合检索或长期记忆。
- 校验来源存在且属于当前群、成员有效、返回结构符合约定。合法来源 ID 不保证答案含义正确，需人工核对原文。
- 只有确认动作会创建任务；重复确认同一建议返回同一任务，重启后仍有效。可能重复的来源 / 标题要求用户显式允许。仅负责人能修改完成状态。
- “今天 / 明天 / 后天”以引用消息的发送时间换算；其他时间表达保留原文，用户自行选择日期。日期表示当天，未实现精确时刻与提醒。
- 页面保留最近 100 次运行；重启后运行列表、未确认建议和忽略状态清空。JSONL 仍在磁盘，新增消息和已确认任务可恢复。
- 短历史直接输入，采用保守字节容量检查，不静默截断。超限时报错；尚未实现历史筛选或精确 Token 计算。
- 身份切换是调试功能，成员校验不等于真实身份认证。未实现注册、邀请、群组 CRUD、实时多人同步、分页或多进程事务。
- 运行记录包含完整输入与响应，保存在本机 `data/`（已被 Git 忽略）。

## 验证

```sh
make go-check
```

新增自动测试覆盖跨群来源拒绝、非成员访问、结构异常、确认持久化 / 幂等、完成权限和磁盘失败不修改内存。实际模型效果以人工核对和运行记录为准，测试使用替身不会掩盖页面中的真实模型错误。

## 本机数据

运行 `make assistant` 默认加载 `local/data/chat-history/history.fixture.json`。原虚构聊天数据已删除。完整整理记录与时间精度说明保留在 `local/data/chat-history/`；图片、链接正文等使用占位符，消息时间来自相邻界面时间段，不是每条消息的精确发送时间。

## Phoenix 评测试验

V2 评测已基于导入聊天准备 23 条案例，参考答案均为待人工审核草稿（`reviewed: false`），未审核不计参考或语义通过率。`make trace` 启动 Phoenix，`make eval-check` 离线检查案例，`make eval` 执行实验；详见 [Phoenix 评测说明](Phoenix评测说明.md)。页面日常交互的 JSONL 与 Phoenix 实验追踪分开，当前仅评测入口上报 Phoenix。

## 本地链路验证

运行 `make assistant-check`，使用真实 `qwen3.5:9b` 和用户提供的历史检查问答、来源校验和提取；再用同一历史中的原始日程片段做回放，检查明确安排提取、确认幂等、负责人完成、重启恢复与 JSONL 日志。临时状态在验证结束后清理，不改当前调试台的消息与任务。

2026-10-11 本机验证：问答正确返回 18:00–19:00 健身、20:00 理发，引用 `wx-0165`。全量提取本次返回空建议；原日程片段回放提取出两项安排，并完成保存和恢复验证。全量提取约 196 秒，命中缓存后的问答约 5 秒；这是单次本机结果，不代表所有问题的速度或语义效果。报告见 `local/data/agent-check/acceptance.json`。当前默认超时调整为 5 分钟。

## 待办提取状态核对

提取版本 `extract-v4` 先生成单项候选，再针对全部原消息逐项核对承诺、负责人及完成/取消状态；只有 active 候选进入确认列表。没有候选时跳过核对，有候选时增加一次本地模型调用。核对须覆盖全部候选并引用本群真实消息，缺失、非法输出或调用失败会使本次运行失败，不直接展示未经核对的候选。
