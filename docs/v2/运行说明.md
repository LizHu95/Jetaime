# V2 最简 Workflow Demo

更新：2026-10-14。当前是可运行的开发调试台，使用固定群组与模拟身份，不是完整多人聊天产品。

## 启动

统一入口 `scripts/dev.py` 自动加载本地环境文件。在仓库根目录启动：

```sh
make assistant
# 等效：python3 scripts/dev.py assistant
make model-check  # 不调用模型，只校验默认配置和密钥存在性
```

首次配置可用 `cp -n services/api/config/models.example.json local/models.json`。编辑各模型参数，并将顶层 `default_profile` 设置为要使用的配置 ID。使用本地模型时先启动 Ollama 并安装所选模型；云密钥保存在 `local/.env`，不再手动 source。

浏览器打开 <http://127.0.0.1:8081/page/assistant/>。服务只允许监听本地回环 IP。无需前端安装或构建，页面嵌入 Go 程序。停止服务使用 Ctrl+C。

## Eino 模型接入与启动选择

模型调用通过项目 `llm.ChatModel` 接口使用 Eino Ollama / OpenAI 兼容组件，当前支持非流式文本聊天。每次启动固定一个模型，问答、提取和审核全部共用；修改模型后重启服务。页面显示当前模型，不允许运行时覆盖。没有自动跨模型故障切换。

模型调用参数统一填写在 `local/models.json`：`provider`、`base_url`、`model`、`output_mode`、`enable_thinking`、`context_tokens`。该文件已被 Git 忽略。配置只保存密钥环境变量名 `api_key_env`，不接受明文 `api_key` 字段。

配置文件顶层 `default_profile` 决定无参数启动时使用的模型。使用百炼时填写真实业务空间地址与模型标识，密钥保存到 `local/.env`（权限 `600`）。入口自动读取该文件并导出到子进程。示例云配置关闭思考模式；其他服务不支持该参数时删除 `enable_thinking`。

```sh
make assistant
# 临时选其他 profile；仍自动加载默认配置文件：
make assistant ASSISTANT_ARGS='-model-profile local-qwen'
```

Go 启动入口默认在 `services/api` 工作目录读取 `../../local/models.json`；Python 评测默认读取仓库根目录的 `local/models.json`。`-model-config` / `--model-config` 可覆盖文件，`-model-profile` / `--model-profile` 可覆盖默认 profile。指定配置文件后，所选 profile 优先于直接模型参数。未配置上下文容量时使用启动参数。

`local/.env` 保存共享开发凭据，飞书启动和打包额外读取 `local/feishu/.env`。已有进程环境变量优先于文件；未在外部设置的变量由飞书专用文件覆盖共享文件。同名凭据不要重复维护。环境文件只解析字面值，支持 `export KEY=value`、引号和注释，不执行 shell 代码。修改文件后重启服务。

直接运行 Go 程序时不会加载环境文件；推荐通过 `make` 或 `scripts/dev.py` 启动。没有本地模型配置文件且没有指定 profile 时，保留默认 Ollama 启动行为。

OpenAI 兼容输出模式可选择 `json_schema`（请求原生 Schema，默认）或 `json_object`（仅请求 JSON 对象，Schema 仍放在提示词中）。请按目标模型实际能力选择，服务端始终执行现有业务校验；不自动降级。上下文容量应按目标模型设置，过长输入明确拒绝，不截断消息。

兼容说明：未指定配置文件时，原有 `-provider`、`-model-url`、`-model`、`-ollama-url` 等直接参数仍可使用；无配置文件且未指定 profile 时，`make assistant` 使用默认 Ollama 配置。新增或修改模型推荐编辑配置文件。

运行轨迹新增 `modelIdentity`：profile、provider、model、baseUrl、outputMode，不含密钥。实验性审核缓存保持默认关闭；云模型缺乏可靠版本指纹时禁用该缓存。失败日志不保存上游错误正文，防止凭据回显。

Go 评测入口和调试台共用配置工厂。可通过统一入口检查或评测：

```sh
make model-check
make eval-check
make eval
# 评测临时切换：
make eval EVAL_ARGS='--model-profile local-qwen'
```

`model-check` 不调用云模型，`eval-check` 只校验案例结构；真实云端连通性和模型效果需要另行联调。

## 调试路径

1. 选择群组和模拟成员，查看启动时固定的模型。默认加载用户提供的微信记录，2 位成员、441 条消息；两个账号已合并为同一位成员。
2. 点击“历史问答 + 引用”，默认问题为“这段聊天里有哪些明确的行动安排？”。点击来源按钮定位原文。
3. 点击“从当前历史提取待办”。调整标题、负责人、日期后确认创建；忽略建议不会保存任务。
4. 在左侧模拟发送消息，选择只保存、发送后问答或发送后提取。触发策略由页面明确选择，未实现模型自动路由。
5. 查看本人待办并标记完成，也可切换成员、取消“仅我负责”查看本群全部任务。
6. 在右侧展开运行步骤，查看隔离后的上下文、实际请求 / Schema、模型原始响应与校验错误，或下载该次运行 JSON。

消息先保存、后调用模型。模型失败不回滚消息；可以直接重试右侧 Workflow，无需重复发送。

## 文件与参数

路径相对 `services/api`，可通过启动参数改动：

| 文件 | 用途 | 参数 |
| --- | --- | --- |
| `../../local/data/chat-history/history.fixture.json` | 可编辑的用户、群组、成员和原始历史；程序只读 | `-fixture` |
| `../../local/data/assistant/state.json` | 模拟新增消息与已确认任务；原子替换保存 | `-state` |
| `../../local/data/assistant/runs.jsonl` | 每次问答 / 提取的完整运行记录 | `-log` |

修改 fixture 后点击“重新读取历史 JSON”。如果与已保存消息 / 任务冲突，拒绝加载并保留原数据。临时实验可指定新的 `-state` / `-log` 文件；不要同时启动两个进程写同一文件。

其他参数：`-ollama-url`（默认 `http://127.0.0.1:11434`）、`-model-timeout`（默认 `5m`）、`-context-tokens`（默认 `98304`）。三个数据文件必须不同。

## 实现与限制

- 两条确定流程：组装当前群历史 → 专用 Prompt / Schema → 一次模型调用 → 校验结果。未引入 Agent Loop、小模型 Router、摘要、混合检索或长期记忆。
- 校验来源存在且属于当前群、成员有效、返回结构符合约定。合法来源 ID 不保证答案含义正确，需人工核对原文。
- 只有确认动作会创建任务；重复确认同一建议返回同一任务，重启后仍有效。可能重复的来源 / 标题要求用户显式允许。仅负责人能修改完成状态。
- “今天 / 明天 / 后天”以引用消息的发送时间换算；其他时间表达保留原文，用户自行选择日期。日期表示当天，未实现精确时刻与提醒。
- 页面保留最近 100 次运行；重启后运行列表、未确认建议和忽略状态清空。JSONL 仍在磁盘，新增消息和已确认任务可恢复。
- 短历史直接输入，采用保守字节容量检查，不静默截断。超限时报错；尚未实现历史筛选或精确 Token 计算。
- 身份切换是调试功能，成员校验不等于真实身份认证。未实现注册、邀请、群组 CRUD、实时多人同步、分页或多进程事务。
- 运行记录包含完整输入与响应，保存在本机 `data/`（已被 Git 忽略）。

## 待办提取状态核对

`extract_todos` 已移除默认注册，当前整理请求由 QA 作文字回答，调试台不再通过默认主 Agent 生成结构化候选。以下为暂留提取实现的处理流程：先生成候选，再核对来源、承诺、负责人及后续状态；只有通过校验的建议进入确认列表。没有候选时跳过状态核对，有候选时可能增加模型调用。未知来源、非法结构或核对失败都不能直接展示候选。

旧的 review cache 实验、模型指纹查询、实验开关与专用脚本已删除。当前不支持 `-experimental-review-cache`，部署与本地调试均使用相同的提取和证据规则。当前工具边界见[主 Agent 设计问答](主Agent设计问答.md)。

## HTTP 入口与路径

`make dev` 使用 `cmd/api` 启动默认开启认证的 API，注册账号注册、登录、退出接口与 `GET /test/healthz`，需要已配置并迁移的 PostgreSQL；编译后的二进制行为相同，无需加 `-auth`。`API_ARGS` 可追加或覆盖启动参数，例如 `make dev API_ARGS='-addr 127.0.0.1:8082'`；仅需连通性检查时使用 `make dev API_ARGS='-auth=false'`。`make assistant` 显式关闭认证并注入 Assistant 模块，保留独立 JSON 调试流程；调试页面位于 `/page/assistant/`，接口统一使用 `/api/assistant/` 前缀。Router 不注册根路径跳转、存活或就绪接口。
