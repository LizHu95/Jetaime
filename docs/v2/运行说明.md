# 服务运行说明

更新：2026-10-23。当前服务使用 PostgreSQL 支持认证、双人群聊、共享主 Agent、记忆检索和提醒。旧 JSON 调试台及离线 Workflow 评测已退役。

## 启动

在仓库根目录准备 `local/.env`、`local/models.json` 和 `local/memory.json`。数据库与记忆配置见 [部署说明](../../deploy/api/README.md)和[记忆说明](历史向量化与增量记忆.md)。统一入口自动加载环境文件，已有环境变量优先。

```sh
make model-check  # 只检查模型配置和密钥存在性
make db-migrate   # 需要已导出的 JETAIME_DATABASE_URL
make dev         # 正式 API，需要数据库、主模型与记忆配置
make web         # 首次运行前在 apps/web 执行 npm ci
```

Web 入口为 `http://127.0.0.1:5173/page/auth/login/`，API 默认监听 `127.0.0.1:8081`。`make dev API_ARGS='-auth=false'` 仅提供健康检查，不连接数据库；`-chat-ai=false` 关闭群聊主 Agent，账号服务仍需要记忆配置。Ctrl+C 停止前台服务。

## 高德官方 MCP

在 `local/.env` 配置 `JETAIME_GAODE_API_KEY`，使用高德控制台申请的 Web 服务类型 Key，然后重启 `make dev`。正式群聊通过官方 MCP Go SDK 的 Streamable HTTP 客户端连接 `https://mcp.amap.com/mcp`，Key 只在服务端加入连接参数。未配置 Key 时不注册高德工具；飞书入口默认不启用真实高德查询。参考[高德官方接入说明](https://lbs.amap.com/api/mcp-server/gettingstarted)。

仅开放 `maps_text_search`、`maps_around_search`、`maps_search_detail`、`maps_geo`、`maps_weather` 及步行、驾车、骑行、公交地铁4种路线工具，不自动注册远端全部工具。`internal/ai/mcpclient` 负责协议连接和有界响应读取；`internal/ai/tools/amap` 负责模型参数、授权回调、结果字段白名单和裁剪；聊天领域 Service 重新检查当前群成员、群与助手状态、触发消息、任务租约和 attempt。授权不通过时不发起外部查询。设备定位仅来自当前发送者主动授权的客户端请求上下文；缺少可用定位、城市或出发地时先询问。

返回模型前重建结构化结果：地点最多5条、地理编码最多3条、路线最多2条、每条路线最多8条必要说明、天气最多4天；文本字段有单独长度限制，最终 JSON 最多8192字节。只保留地点ID、名称、地址、可用坐标/评分/人均/营业时间、路线距离与预计耗时、上下车站及天气等字段，移除照片、图片URL、路线折线、完整途经站和未知字段。数量或文本被截短时返回 `truncated=true`；硬预算按完整条目裁剪，保证 JSON 有效。缺失字段不补造，查询失败返回 `unavailable`，有效空结果返回 `empty`。原始 MCP 响应和服务端错误文本不进入模型观察与 Tool Trace。

每次 Tool 调用独立建立和关闭 MCP 会话，禁用自动重连、后台 SSE、模型采样和根目录共享；HTTP 请求超时15秒、工具超时30秒，原始响应/SSE事件上限2MiB。配置高德工具的主 Agent 最多8轮工具决策，其他注册表最多3轮；参数修复也计入轮次。最后一轮工具决策前提示收尾，额度用尽后，注册了收尾工具的 Agent 额外获得1轮最终答复。该轮目录、JSON Schema 与服务端执行检查只允许 `respond`（主动介入也允许 `remain_silent`），不再执行查询或写操作；保留已有工具结果、卡片引用、来源校验与每轮上下文硬预算。最终输出仍无效则失败，不无限重试。周边查询默认3公里、上限10公里，文本搜索强制限制在指定城市内。密钥URL不会放入模型请求或错误日志。

地点换批：初始上下文携带从本群近期已展示卡片提取的 `recentRecommendedPlaces`（最多20个去重的地点ID与名称，遵守原触发序号边界），独立于可裁剪的聊天正文。用户要求“换一批”或避免重复时，Agent 在文本或周边搜索中设置本地选项 `excludePrevious=true`；该选项不传给高德。后端在本次执行内持续过滤已推荐地点，同时对单批结果按地点ID去重，最终 `respond` 也禁止选择被排除的卡片。新候选不足时调整搜索条件或如实说明，不用旧地点凑数。正常追问旧店详情或路线不启用排除；不新增数据库表，排除范围限于当前上下文可见的近期已展示地点。

主 Agent 的执行上下文先保留当前触发消息和直接引用，再补最多 6 条近期原文，可选背景合计仍限 4KiB。主动识别继续使用最近 30 条窗口；进入执行阶段后，只固定保留触发消息、原有直接引用及识别出的意图/障碍证据，再补最多 6 条近期原文，不把识别窗口整包传给执行模型。执行选择标记为 `execution-context-v2`，不修改原消息或识别阶段快照。

首轮把系统提示、完整工具目录/Schema、必需消息与输出预留先计入预算，并为工具反馈预留空间：普通工具目标 4KiB，高德工具目标 8KiB；然后按剩余空间裁掉超额的可选背景。工具反馈预留是目标，不能因此丢弃必需证据或扩大模型容量；必需内容能通过硬预算但无法留足目标空间时仍可执行。后续每轮继续统一计算累计工具结果/修复反馈，超限时只裁剪可选聊天背景，保留当前触发消息、直接引用、主动识别的意图与障碍证据、工具引用来源和全部工具反馈。Trace 的 `step.context_budget` 记录输入估算、输出预留、目标工具反馈预留、实际余量与消息数，`step.context_trim` 记录发生裁剪的轮次和消息数。必需证据仍超限时在调用模型前拒绝。模型配置与保守字节估算规则保持不变。主动介入只能在触发消息带有有效客户端定位时使用 `current`；地点不足则澄清或保持沉默。

可测试：`@AI 上海五角场附近中午吃什么，清淡点`、`@AI 从上海五角场地铁站怎么去三门路地铁站，远不远`。清淡等条件用于本次推荐，不能由地点类别推断商家保证少油少盐；预报仅覆盖实际返回日期。

单元和协议测试纳入 `make check`。授权集成测试在设置隔离的 `JETAIME_TEST_DATABASE_URL` 后运行 `go test -race ./internal/chat -run TestExternalToolAuthorization`。真实接口测试需显式设置 `JETAIME_GAODE_LIVE_TEST=true` 和 Key，在 `services/api` 下运行 `go test ./internal/ai/tools/amap -run '^TestLiveMCP$' -v -count=1`；直接 Go 命令不自动加载 `.env`。该测试会使用公开地标消耗少量查询配额，且验证经过 Tool 校验后的裁剪结果。

### 客户端定位上下文

群聊配置中的“发送消息时使用位置”开关首次开启时请求浏览器单次定位，并按登录用户在本机保存开关；只持久化开关，不保存坐标。打开或刷新聊天不会获取位置。开启后，每条消息发送前都重新获取并附带当前位置，包括普通群聊，不按关键词、是否 @AI 或助手是否启用筛选。没有 30 秒缓存或位置复用窗口，浏览器定位请求设置 `maximumAge: 0`。AI 自行判断是否需要使用位置；明确指定起点时优先使用指定地点。

位置仅作为本次发送请求中的私有上下文，不在群消息正文、消息响应或实时通知中展示。没有定时轮询或后台追踪。正式环境需要 HTTPS；localhost 可用于开发。关闭开关后不获取或附带位置。拒绝授权、超时或定位误差超过 1 公里时关闭开关并提示手动输入地点，该条消息仍正常发送，不改用 IP 定位。网络重试属于同一条消息，保留同一消息ID及原请求位置，避免改变已接收请求的起点；原位置超过服务端接收期限时去掉定位后重试。

发送消息时，接口的可选 `clientContext.location` 携带 `longitude`、`latitude`、`accuracyMeters`、`capturedAt` 和 `coordinateSystem`（浏览器为 `wgs84`）。后端校验经纬度、精度和时间，本次任务的位置证据最多有效 5 分钟，容许 30 秒时钟误差，这是本次任务证据有效期，并非客户端缓存。在通过群权限后将位置与该条触发消息绑定，独立保存到 `message_client_locations`，从服务端接收起最多保留 5 分钟，不加入消息或任务列表响应，主动和被动 AI 任务都只取自己触发消息的发送者位置，不继承其他消息或群成员的位置。到期即不可读取，后台每分钟清理到期记录，服务启动也执行清理；停机期间到期记录在下次启动清理。数据库迁移随正常服务启动自动执行。

任务执行时使用当前 Web 服务 Key 调用高德坐标转换接口，将 WGS84 转为 GCJ02；地图搜索、天气和路线仍走官方 MCP。转换超时 5 秒，响应限 8KiB，禁用重定向，失败不使用原始坐标冒充高德坐标。模型只接收 `request.locationStatus`（`available` 或 `unavailable`），不接收客户端精确坐标；周边工具的 `location` 或路线的 `origin` 使用 `current`，经原有任务授权后由后端替换，再次检查有效期。缺少 `locationStatus` 表示本轮没有位置上下文，不能据此判断定位服务故障；模型应提示开启群聊配置中的“发送消息时使用位置”或手动提供地点。用户明确指定起点时仍使用指定地点。公交和天气需要城市，定位本身不推断城市。

带客户端定位的请求所生成的路线卡片，只提供目的地地图入口，避免在群共享链接中包含私人起点坐标；距离、耗时和裁剪后的路线说明仍可正常展示。手动指定地点且未附定位的请求保留原有路线链接。精确定位不沉淀为长期偏好。

### 地点和路线卡片

群聊消息的 `agentResult.cards` 是可选业务结果字段，旧消息继续只显示文字。后端将成功高德工具结果转换为地点或路线候选，主 Agent 仅在本次执行范围内保存候选，并把 `cardRefs`（引用、类型、标题）提供给模型。模型在 `respond.cards` 中最多选择5个 `{ref, reason}`，不能提交名称、价格、路线数字或链接。引用必须来自本轮成功查询；不存在、重复、跨执行的引用及额外事实字段均拒绝。卡片事实由后端组装，缺失价格、评分和路线数值保留 `null`，最终卡片合计上限12KiB，推荐理由每张最多160字。卡片随现有消息JSONB保存，历史补拉、刷新和双方阅读复用原有群权限，无新增公开查询接口。

地点卡片显示店名、推荐理由、地址、可用人均/评分/营业时间和高德地图入口。路线卡片显示方式、预计时间、距离、可展开说明和地图路线入口。地图URL由后端按高德URI规范生成，不包含Key；前端只接受 `https://uri.amap.com/marker` 和 `/navigation`。地图中重新计算的路线可能随实时情况变化，不代表锁定卡片中的某个备选方案。

“怎么去”将包含地点名称、城市、地址的追问追加到当前输入草稿，并选中 @AI；用户可以补充出发地后发送。按钮不会自动发消息或覆盖已有草稿，助手停用或正在发送时不可操作。完整行程卡片、独立换批状态和长期偏好管理尚未实现。

## Eino 模型接入与启动选择

模型调用通过项目 `llm.ChatModel` 接口使用 Eino Ollama / OpenAI 兼容组件，当前支持非流式文本聊天。每次启动加载主模型和候选列表，问答、提取和审核全部共用。页面显示配置的主模型，不允许运行时覆盖；实际调用可在失败后自动切换到候选。修改模型配置后重启服务。

模型调用参数统一填写在 `local/models.json`：`provider`、`base_url`、`model`、`output_mode`、`enable_thinking`、`context_tokens`。该文件已被 Git 忽略。配置只保存密钥环境变量名 `api_key_env`，不接受明文 `api_key` 字段。

配置文件顶层 `fallback_profiles` 是按优先级排列的候选 profile ID，例如：

```json
"fallback_profiles": [
  "cloud-qwen-max-2026-06-08",
  "cloud-qwen-plus-2026-05-26",
  "cloud-qwen-max-2026-05-20",
  "cloud-qwen-flash-2026-07-15",
  "cloud-qwen-max-2026-05-17",
  "cloud-qwen-flash",
  "cloud-qwen-max"
]
```

首次请求优先使用 `default_profile`（或 `-model-profile` 指定的模型）。连接失败、HTTP 错误、单次尝试超时、空响应或不完整响应时，按顺序尝试其他候选，每次调用最多尝试每个候选一次；成功后后续请求优先使用该候选，直到它也失败，再循环尝试其余模型。不会主动探测或自动切回主模型。省略候选列表时保留原来的单模型行为。重复的 ID（包括主模型）只保留一次，未知 ID、无效配置或缺失任何候选密钥会在启动时报错。

`-model-timeout` 约束整个模型调用，时间在各候选间均分，并受调用方更短的剩余期限约束，给后备模型预留尝试时间；请求取消后立即停止切换。各候选独立执行上下文容量检查，容量不足时跳过，不截断输入。请求参数错误直接拒绝；业务输出校验仍由上层执行，不触发自动切换。全部失败时返回脱敏的候选错误。运行记录中的 `modelIdentity` 保留配置主模型身份，实际尝试的模型见 `llm.call` span 和失败切换日志。

默认 profile 为 `cloud-qwen-max-2026-06-08`，对应主模型 `qwen3.7-max-2026-06-08`；`cloud-qwen` 保留为手动可选的 `qwen3.7-plus` 配置。示例候选列表覆盖指定日期版本及 Flash / Max 别名，其中与主 profile 相同的项会去重。所有云端候选沿用同一业务空间地址、密钥环境变量和 32768 的应用上下文预算；请按账号实际开通情况填写地址。`local-qwen` 保留为手动可选 profile，需要本地兜底时可将其追加到 `fallback_profiles`。实际运行读取 `local/models.json`，已有配置也须更新，不能只修改示例文件；运行中的服务需要重启后生效。

配置文件顶层 `default_profile` 决定无参数启动时使用的模型。使用百炼时填写真实业务空间地址与模型标识，密钥保存到 `local/.env`（权限 `600`）。入口自动读取该文件并导出到子进程。示例云配置关闭思考模式；其他服务不支持该参数时删除 `enable_thinking`。

```sh
make dev
# 临时选其他 profile；仍自动加载默认配置文件：
make dev API_ARGS='-model-profile local-qwen'
```

Go 启动入口默认在 `services/api` 工作目录读取 `../../local/models.json`。`-model-config` 可覆盖文件，`-model-profile` 可覆盖默认 profile。指定配置文件后，所选 profile 优先于直接模型参数。未配置上下文容量时使用启动参数。

`local/.env` 保存共享开发凭据，飞书启动和打包额外读取 `local/feishu/.env`。已有进程环境变量优先于文件；未在外部设置的变量由飞书专用文件覆盖共享文件。同名凭据不要重复维护。环境文件只解析字面值，支持 `export KEY=value`、引号和注释，不执行 shell 代码。修改文件后重启服务。

直接运行 Go 程序时不会加载环境文件；推荐通过 `make` 或 `scripts/dev.py` 启动。没有本地模型配置文件且没有指定 profile 时，保留默认 Ollama 启动行为。

OpenAI 兼容输出模式可选择 `json_schema`（请求原生 Schema，默认）或 `json_object`（仅请求 JSON 对象，Schema 仍放在提示词中）。请按目标模型实际能力选择，服务端始终执行现有业务校验；不自动降级。上下文容量应按目标模型设置，过长输入明确拒绝，不截断消息。

兼容说明：未指定配置文件时，原有 `-provider`、`-model-url`、`-model`、`-ollama-url` 等直接参数仍可使用；无配置文件且未指定 profile 时，`make dev` 使用默认 Ollama 配置。新增或修改模型推荐编辑配置文件。

运行轨迹新增 `modelIdentity`：profile、provider、model、baseUrl、outputMode，不含密钥。失败日志不保存上游错误正文，防止凭据回显。

独立命令 `cmd/model-check` 复用服务端模型配置工厂：

```sh
make model-check
make model-check MODEL_CHECK_ARGS='-model-profile local-qwen'
```

该命令校验配置和密钥存在性，不调用模型，不检查真实服务连通性或效果。

## HTTP 入口与路径

`make dev` 默认提供认证、好友、群聊、提醒、通知和 `GET /test/healthz`。业务接口使用 `/api/` 前缀，页面使用 `/page/` 前缀。路由集中在 `internal/httpapi/router.go`；不注册根路径跳转，旧 `/page/assistant/` 和 `/api/assistant/` 路由已移除。健康检查固定返回测试 JSON，不表示数据库或模型就绪。
