# 主动介入 15／30 条窗口对照

`scripts/intervention_eval.py` 编译独立 `cmd/eval-intervention`，直接调用生产 `intervention.Judge.Discover`。同一案例先保留完整30条，再严格取后15条，当前真人触发消息计入窗口；AI历史消息也计数。两组使用相同模型、提示词、Schema及生产证据校验，按固定种子打乱执行顺序，每次新建模型适配器和识别器。

本入口不修改生产 `InterventionMessageLimit=30`，不调用历史核验、工具、主 Agent、数据库或消息投递，不初始化 Phoenix。`verify` 是识别候选结果，单独记录；无法代表补证后的最终决定。当前比较只回答窗口对首阶段识别的影响。

## 离线检查

```sh
make eval-intervention-check
python3 scripts/intervention_eval.py \
  --cases local/data/evals/proactive-window-20261101-draft-r1/cases.json \
  --dry-run
```

预检校验窗口、群组、时间顺序、唯一ID及真人触发，不解析模型配置、不创建模型，不加载 `.env` 或导出 Trace。Go编译可能需要已安装的依赖，预检本身无推理调用。

## 真实模型执行

```sh
python3 scripts/intervention_eval.py \
  --cases local/data/evals/proactive-window-20261101-draft-r1/cases.json \
  --repetitions 1
```

20例 × 两种窗口 × 一次为40次识别执行。每阶段沿用生产最多一次结构修复，因此API调用数可能更高。没有额外自动重试；模型fallback关闭。`--repetitions 3` 为120次执行。`--seed` 默认20261101，`--case-timeout` 默认90s，覆盖该次识别与结构修复。

任务模型使用 `local/eval-settings.json` 的 `modelProfile`，未设置则用 `local/models.json` 的默认profile；可以用 `--model-profile` 显式覆盖。凭据从现有环境和 `local/.env` 读取，不复制凭据文件，也不改变业务默认模型。子进程剔除业务数据库、高德和Phoenix配置。

默认在受Git忽略的 `outputs/evals/intervention/<UTC时间>-<随机值>/` 新建私有目录。保留案例原字节、所选公开模型配置、Go源码和提示词归档、逐文件哈希、二进制及哈希、分支/提交/dirty、运行顺序、实际请求与响应、步骤、用量和耗时。结果文件600、目录700，拒绝覆盖旧目录。执行错误仍保存已完成结果，返回非零；源文件或案例运行期间变化时拒绝将结果视为可比。没有供应商用量时保留null，不补零。

查看 `report.md`、`summary.json`、`results.json`；`progress.log` 只有案例ID、动作及状态，完整对话仅保留在私有原始报告中。

## 参考与评分

案例结构是 `proactive-window-dataset-v1`，不是主动 @AI 的 `eval_replay.py` 契约。`input30` 是唯一推理输入；参考、名称、类别、来源和隐藏消息不传给模型。

- `reference.productAction`：完整证据下的产品目标。
- `windowReferences[15/30].action`：仅有对应可见证据时的预期。
- `review.reviewed`：参考是否经过人工审核。

两种预期分开报告。例如早先拒绝落在15条之外时，15条局部识别即使合理，仍计入相对于完整产品目标的误打扰。`verify` 既不是已经介入，也不是最终静默。失败执行单列，不进入成功样本的质量分母。

未审核案例只产生 `exploratoryOnly` 诊断，`reviewedQuality=null`。不能把探索性预期匹配称为正式准确率。审核和标签修订另建版本，不能覆盖历史案例或运行报告。

首批20例为3例真实静默目标、17例合成场景，其中10例参考已有开发用例；6例包含决定性的窗口外证据。真实窗口有重叠，全部正例为合成，且仅一次重复，不支持推断线上误打扰率或稳定性。用量、耗时仅代表当前识别阶段，不能推断包含检索及主Agent的完整收益。
