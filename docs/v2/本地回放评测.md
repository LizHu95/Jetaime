# 本地历史回放与 Phoenix 实验

实现位于 `feat/debug`。回放不启动 API、不构造业务数据库连接、不启动聊天/记忆/提醒 Worker。输入是导出的 `messages.jsonl`，输出是本地私有报告；真实网络请求仅限显式选定的模型服务和 Phoenix。

## 先验证工程入口

在仓库根目录执行：

```sh
make eval-replay-check
```

包括有未来消息的合成快照、跨群/截止边界、固定检索、嵌套模型 token 统计、缺失录制、提醒隔离、超时和无网络预检。合成示例不是实际质量评测集。

## 真实消息与案例

### 从云端导出新快照

```sh
python3 scripts/export_chat_snapshot.py --host jetaime-server
# 限定会话时显式提供一个或多个 --group-id UUID。
```

导出器经 SSH 在服务器读取 `~/api/.env`，凭据只传入远程 `psql` 的环境，不放进命令参数或返回日志。使用 `REPEATABLE READ READ ONLY` 一致性事务及超时，仅导出消息、发送者显示名和ID、序号、@AI、回复关系及时间，不导出账号密码、会话令牌等字段。默认读取所有会话，支持会话过滤；超过 `--max-messages` 时失败，不静默截断。云端没有文件写入或数据修改。

新快照保存于被 Git 忽略的 `local/data/evals/snapshots/chat-messages-<UTC时间>-<随机值>/`。`messages.jsonl` 为只读文件；`manifest.json` 记录消息数、会话计数、哈希、事务隔离级别及导出时间。目录权限700、文件权限400/600，不覆盖旧快照。导出本身不会调用模型或上传到Phoenix。

使用输出路径生成真实候选题：

```sh
python3 scripts/eval_replay.py prepare \
  --snapshot local/data/evals/snapshots/<新目录>/messages.jsonl \
  --output local/data/evals/replay/cases-real-<新版本>.json --limit 20
```

`prepare` 默认抽最近的请求；做A/B/C比较时还应从全部请求中挑选有代表性的案例，避免连续“换一批”占据样本。真实材料及审核文档继续放在 `local/`。20题只是候选数量，不要求真实数据强行符合合成题的场景比例。

消息快照不包含定位、推荐卡片、提醒草稿、成员关系历史或高德原始返回。提醒补全、附近推荐、多轮指代等案例需要这些状态时，先补证据或排除，不能把回放缺失当成策略失败。定位在服务端还有过期清理机制，旧定位不一定能恢复；不可用今天的响应冒充过去的天气或路线录制。

A/B/C统一入口接受 `--snapshot`、`--cases`、`--protocol` 指向私有真实题集。协议的 `dataOrigin` 设置为 `production-chat-export`，`cases` ID需与题集一一匹配；缺状态的题标记 `readiness=blocked_missing_state_or_recordings`。在线入口会拒绝这些题，即使reviewed被误设为true。恢复证据后再更新状态，或冻结一份排除这些题的新题集及匹配协议。

2026-11-01 已通过只读事务导出313条消息（2个会话、47个@AI请求），真实候选审核保存在本机 `local/data/evals/tool-search-real-20261101/review.md`。20个候选中12个进入预期/来源审核，另8个依赖缺失状态或地图录制。全部仍待审核，未调用模型或上传Phoenix。

### 历史导出示例

已导出的原文位于主工作目录的 `local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl`。不复制或修改该冻结文件。生成新的未审核案例文件：

```sh
python3 scripts/eval_replay.py prepare \
  --snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl \
  --output local/data/evals/replay/cases-draft-v2.json \
  --limit 20
```

`prepare` 从实际 @AI 请求中选择案例，截止点在原问题之前，原问题被转为本次回放的合成提问。原历史 AI 回复仅作为未审核 `expected.reference`，绝不会作为输入或自动视为真值。它不会自动编造参考答案、检索命中或评分标签。

本次已生成 `local/data/evals/replay/cases-draft-v1.json`，含20条真实请求，全部 `reviewed=false`。审核时：

1. 核对 `groupId`、`actorId`、`cutoffSeq`、`at` 和问题；需要时换成自编问题。
2. 对历史问答，将所需原文 ID 填入 `retrievedMessageIds`。这是固定检索回放，**不测向量/全文检索排序**。
3. 在 `expected` 中填写 `requiredTools`、`forbiddenTools`、`requiredSourceIds`、`answerContainsAll`。关键词包含检查不等于语义正确性，复杂答案需人工核对 `reference`。
4. 确认后将该题 `reviewed` 设为 true。未审核题仍可跑，只有执行状态和录制完整性分数，没有答案/来源/工具期望评分。
5. 给套件设置新 `version` 并冻结。不要修改运行中的文件；改变内容会生成不同 SHA256 和 Phoenix 数据集。

一题的结构见 `evals/replay/cases.example.json`。每个案例只允许使用一个群中 `seq <= cutoffSeq`、且不晚于 `at` 的消息；提问使用稳定的独立消息 ID 和下一序号。发送者从可见原文推导，这是评测隔离契约，不是生产成员权限测试。导出文件没有完整成员关系、历史定位或提醒草稿，因此当前不覆盖这些状态恢复。

`mapFixtures` 按工具名和**实际发给高德的规范化参数**严格匹配：

```json
{
  "tool": "maps_weather",
  "arguments": {"city": "上海"},
  "response": {"city": "上海", "forecasts": [
    {"date": "2026-10-30", "dayweather": "晴", "nightweather": "晴", "daytemp": "22", "nighttemp": "16"}
  ]}
}
```

响应是官方调用器返回的原始业务 JSON，再由真正的高德工具裁剪校验。缺录制会计数并使 `map_fixtures_complete=false`，绝不回落真实高德请求。城市/关键词可能有多种合理写法，逐项补录等价参数；不能用通配响应掩盖错误参数。

提醒保留真正工具的参数/原文校验，业务依赖替换为每次独立的内存测试替身。报告显式记录 `simulatedReminderOperations`；不证明生产持久化、幂等或投递正确，不恢复线上提醒。

## 本地运行真实模型

不需要 PostgreSQL、memory.json 或高德密钥。默认复用 `local/models.json` 和 `local/.env` 中的模型密钥；启动器移除数据库和高德密钥环境变量。可在 `local/eval-settings.json` 独立选择评测模型，业务 `default_profile` 保持原值。每题固定时间、全新状态，每次独立重复。模型 fallback 被关闭，避免不同题悄悄切模型。

```sh
make eval-replay EVAL_ARGS='-snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl -cases local/data/evals/replay/cases-draft-v1.json -dry-run -output -'

make eval-replay EVAL_ARGS='-snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl -cases local/data/evals/replay/cases-draft-v1.json -repetitions 3 -case-timeout 300s -output outputs/evals/replay/A-run-1.json'
```

预检不创建模型、不访问 Phoenix，即使环境中存在线上配置也不联网。报告文件拒绝覆盖，权限600；实际问题运行失败仍保存已完成结果并返回非零状态。上游未提供用量时 token 为 null，不记为0。累计用量涵盖主模型及 QA/时间总结内部模型调用，每次只计一次；字节估算单独展示。

## Phoenix 数据集、实验与 Trace

客户端固定为 `arize-phoenix-client==3.5.0`，Python >=3.11：

```sh
uv venv --python 3.11 local/eval-replay-venv
uv pip install --python local/eval-replay-venv/bin/python -r evals/replay/requirements.txt
```

将本机端口转发到云端 Phoenix。此通道不访问业务数据库：

```sh
ssh -N -L 127.0.0.1:16006:127.0.0.1:6006 jetaime-server
```

在另一个终端：

```sh
local/eval-replay-venv/bin/python scripts/phoenix_replay.py \
  --snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl \
  --cases local/data/evals/replay/cases-draft-v1.json \
  --experiment A-feat-debug-run1 --repetitions 3 \
  --endpoint http://127.0.0.1:16006
```

先加 `--dry-run` 可仅本地预检，连 SDK 都不会初始化。正式命令会创建或复用由套件/快照哈希命名的数据集，使用 SDK 的真正 task 逐题调用本地 Go 二进制并上传评分，不是把已有结果伪装成实时实验。

Phoenix task 的 Trace Context 传给 Go，Agent/工具/模型成为同一 Trace 的子节点。实验输出包含真实 `traceId`；`eval.case_id`、快照哈希、分支/提交信息也在链路中。独立 Trace 项目为 `jetaime-eval`。默认不上传 Trace 正文，使用 `--capture-content` 可显式打开；数据集本身会包含问题和参考答案，实验输出包含最终答案。完整模型请求与原文保留在 `outputs/evals/replay/` 的私有报告中。

评分包括执行成功、录制完整性，以及已审核题的工具/来源/关键词断言；指标包含供应商 token、累计输入估算、搜索次数和总耗时。可另启用下述 LLM 语义裁判，原有断言不变。Phoenix 自身 task 耗时还包含子进程启动、裁判调用和 Trace flush，因此比较 Agent 耗时应看输出中的 `durationMs`。

### 评测专用模型与语义裁判

`local/eval-settings.json` 可从 `evals/replay/settings.example.json` 复制。当前本地配置为：

```json
{
  "modelProfile": "cloud-qwen-flash",
  "judgeProfile": "cloud-qwen-flash"
}
```

两个 profile 均从 `local/models.json` 解析。被测 Agent 及其内部模型调用使用 `modelProfile`，评分裁判使用 `judgeProfile`，业务模型默认值不变。没有此设置文件时维持原行为：任务使用模型配置默认值，裁判关闭。显式模型参数优先；指定另一份模型配置且未指定任务 profile 时，Phoenix 使用该文件的默认值。直接 Go 回放入口只执行 Agent；语义裁判通过 Phoenix 入口执行。

```sh
# 加在原有 Phoenix 命令后，可明确选择两个角色：
--model-profile cloud-qwen-flash --judge-profile cloud-qwen-flash
# 只运行原有规则评分：
--no-judge
```

每次成功的 Agent 回放最多增加一次裁判请求，不启用重试或 fallback。裁判同时读取审核参考、最近消息、已检索/引用/必需来源及其相邻消息、实际工具参数/结果和最终展示卡片；消息按同一群组、截止序号及时间过滤，不把历史 AI 回复当真值。不发送整个群历史或原始模型提示词；证据超过预算则明确标为 `not_scored`，不静默截断。未审核、没有参考、执行失败或缺地图录制的结果也不产生语义通过分。

当前评分版本为 `replay-judge-v2`，独立规则版本为 `replay-checks-v1`。Phoenix 分开记录以下八项，不与旧v1的五项LLM评分合并：

| 评分 | 标记 | 含义 |
| --- | --- | --- |
| `semantic_correctness` / `semantic_completeness` / `semantic_grounding` | LLM | Flash原始三维语义判断 |
| `semantic_quality` | LLM | 三项原始语义分的汇总，规则检查不改写这些分数 |
| `card_evidence` | CODE | 展示卡片与本轮成功工具结果的身份、营业时间、价格、评分、路线数值及链接核对 |
| `reminder_consistency` | CODE | 模拟操作数、提交参数、实际保存值、负责人、状态及验证来源核对 |
| `tool_policy` | CODE | 必需/禁止工具调用核对，地图违规不会归入提醒维度 |
| `calibrated_quality` | CODE | 原始语义分与适用规则的组合；任一失败则不通过，必要证据缺失且无确定失败时为空 |

没有卡片或提醒断言时对应项不适用。卡片身份绑定本轮具体地点/路线，不能借用另一地点的数据；字符串数值与数值类型等价，营业时间的空格、全角冒号及等价区间分隔符可归一化。已知价格或评分为空时不能填造数值。可选字段未展示由语义完整性判断，规则检查不把省略字段直接当虚假事实。原始模型分与规则发现的冲突会同时保留，避免规则覆盖后掩盖裁判漏检。

裁判输入包含同一份截止点前证据，并在JSON之后以可读段落展开当前问题、审核参考、完整最终回答和卡片，避免长历史及JSON换行转义掩盖回答后半段的条件说明。`modelDimensions` 保存Flash原始三项；兼容输出中的 `dimensions.reminder` 来自独立规则，标记 `method=CODE`，不再让模型为地图违规给提醒扣分。

每题保留 `judgements/<原报告文件名>.json`，包含原报告/输入哈希、裁判模型、提示词/实现版本、规则版本/哈希、理由和独立用量。原始 Go 报告不改写。`models.json` 保存本次冻结的无密钥配置。裁判费用和耗时只进入 `judge.metrics`，不并入 Agent 指标。

裁判请求或输出格式错误时，评分为空、状态为 `error`，脚本返回非零状态；普通语义不通过仍作为辅助证据保存。尚未记录的私有起点无法重建路线卡片的来源身份时，规则项为 `unavailable`，不能默认为通过。卡片推荐理由、正文自由表述与历史语义仍需模型及人工复核，结构化字段通过不代表整体质量正确。

tool-search汇总将独立规则检查失败纳入 `failures`，与原有规则失败一起使对照入口返回非零状态；仅有LLM语义失败继续作为辅助证据，不增加自动语义质量门槛。

Agent 与裁判当前同为 Flash，需要用人工核对的正负样例校准，组合总分也不能直接作为独立验收结论。保存结果的离线校准只能另建评分实验，明确标记 `posthoc_saved_outputs_only` 和零次Agent执行；保留来源报告哈希、变异方式、标签来源和重复次数，不将其伪装为新Agent回放。旧实验、旧模型快照及旧评分均保持原样，切模型或评分版本后的结果另建实验，不与旧版本汇总成同一轮对照。

## 不切分支运行 B、C

启动器支持用 Go 文件 overlay 将**同一份回放代码**编译到指定分支上，不修改 B、C 的源码或提交。真正的 Agent、提示词、工具实现来自目标工作目录；目录注册桥只支持已识别的生产注册形态，未知形态拒绝构建，避免静默跑成A。构建结果记录 `harnessSha256`、工具策略、目标分支/提交/dirty 和二进制哈希。

```sh
local/eval-replay-venv/bin/python scripts/phoenix_replay.py \
  --source-root /Users/bytedance/.codex/worktrees/tool-search-b/Jetaime \
  --env-file /Users/bytedance/Documents/privacy/code/Jetaime/local/.env \
  --model-config /Users/bytedance/Documents/privacy/code/Jetaime/local/models.json \
  --snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl \
  --cases local/data/evals/replay/cases-draft-v1.json \
  --experiment B-run1 --repetitions 3
```

C将 source-root 替换为 `tool-search-c/Jetaime`，实验名改为 `C-run1`。在 feat/debug 目录执行同一版脚本，相同套件会复用同一 Phoenix 数据集版本。每题使用相同录制、相同固定检索、相同模型配置；运行中修改快照、套件、配置或二进制会被拒绝。

注意当前 B/C 从 `a9cca3a` 开发，而 feat/debug 后来又增加了天气 current 逆地理解析。基础代码已不完全相同；正式严格对照前需要统一非实验改动，或选用原共同基线A。回放工具不会自动合并、重置或变基分支，也不将上述不同版本的结果宣称为纯加载策略差异。

当前只支持独立问题和固定历史回放，不把生成答案追加成下一题输入；真正连续追问会话回放是后续扩展。已导出的原文和历史评测快照均保持不变。
