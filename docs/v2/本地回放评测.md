# 本地历史回放与 Phoenix 实验

实现位于 `feat/debug`。回放不启动 API、不构造业务数据库连接、不启动聊天/记忆/提醒 Worker。输入是导出的 `messages.jsonl`，输出是本地私有报告；真实网络请求仅限显式选定的模型服务和 Phoenix。

## 先验证工程入口

在仓库根目录执行：

```sh
make eval-replay-check
```

包括有未来消息的合成快照、跨群/截止边界、固定检索、嵌套模型 token 统计、缺失录制、提醒隔离、超时和无网络预检。合成示例不是实际质量评测集。

## 真实消息与案例

已导出的原文位于主工作目录的 `local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl`。不复制或修改该冻结文件。生成新的未审核案例文件：

```sh
python3 scripts/eval_replay.py prepare \
  --snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl \
  --output local/data/evals/replay/cases-draft-v2.json \
  --limit 20
```

`prepare` 从实际 @AI 请求中选择案例，截止点在原问题之前，原问题被转为本次回放的合成提问。原历史 AI 回复仅作为未审核 `expected.reference`，绝不会作为输入或自动视为真值。它不会自动编造参考答案、检索命中或评分标签。

本次已生成 `local/data/evals/replay/cases-draft-v1.json`，含20条真实请求，全部 `reviewed=false`。审核时：

1. 核对 `groupId`、`actorId`、`cutoffSeq`、`at` 和问题；需要时换成自编问题。
2. 对历史问答，将所需原文 ID 填入 `retrievedMessageIds`。这是固定检索回放，**不测向量/全文检索排序**。
3. 在 `expected` 中填写 `requiredTools`、`forbiddenTools`、`requiredSourceIds`、`answerContainsAll`。关键词包含检查不等于语义正确性，复杂答案需人工核对 `reference`。
4. 确认后将该题 `reviewed` 设为 true。未审核题仍可跑，只有执行状态和录制完整性分数，没有答案/来源/工具期望评分。
5. 给套件设置新 `version` 并冻结。不要修改运行中的文件；改变内容会生成不同 SHA256 和 Phoenix 数据集。

一题的结构见 `evals/replay/cases.example.json`。每个案例只允许使用一个群中 `seq <= cutoffSeq`、且不晚于 `at` 的消息；提问使用稳定的独立消息 ID 和下一序号。发送者从可见原文推导，这是评测隔离契约，不是生产成员权限测试。导出文件没有完整成员关系、历史定位或提醒草稿，因此当前不覆盖这些状态恢复。

`mapFixtures` 按工具名和**实际发给高德的规范化参数**严格匹配：

```json
{
  "tool": "maps_weather",
  "arguments": {"city": "上海"},
  "response": {"city": "上海", "forecasts": [
    {"date": "2026-10-30", "dayweather": "晴", "nightweather": "晴", "daytemp": "22", "nighttemp": "16"}
  ]}
}
```

响应是官方调用器返回的原始业务 JSON，再由真正的高德工具裁剪校验。缺录制会计数并使 `map_fixtures_complete=false`，绝不回落真实高德请求。城市/关键词可能有多种合理写法，逐项补录等价参数；不能用通配响应掩盖错误参数。

提醒保留真正工具的参数/原文校验，业务依赖替换为每次独立的内存测试替身。报告显式记录 `simulatedReminderOperations`；不证明生产持久化、幂等或投递正确，不恢复线上提醒。

## 本地运行真实模型

不需要 PostgreSQL、memory.json 或高德密钥。默认复用 `local/models.json` 和 `local/.env` 中的模型密钥；启动器移除数据库和高德密钥环境变量。每题固定时间、全新状态，每次独立重复。模型 fallback 被关闭，避免不同题悄悄切模型。

```sh
make eval-replay EVAL_ARGS='-snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl -cases local/data/evals/replay/cases-draft-v1.json -dry-run -output -'

make eval-replay EVAL_ARGS='-snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl -cases local/data/evals/replay/cases-draft-v1.json -repetitions 3 -case-timeout 300s -output outputs/evals/replay/A-run-1.json'
```

预检不创建模型、不访问 Phoenix，即使环境中存在线上配置也不联网。报告文件拒绝覆盖，权限600；实际问题运行失败仍保存已完成结果并返回非零状态。上游未提供用量时 token 为 null，不记为0。累计用量涵盖主模型及 QA/时间总结内部模型调用，每次只计一次；字节估算单独展示。

## Phoenix 数据集、实验与 Trace

客户端固定为 `arize-phoenix-client==3.5.0`，Python >=3.11：

```sh
uv venv --python 3.11 local/eval-replay-venv
uv pip install --python local/eval-replay-venv/bin/python -r evals/replay/requirements.txt
```

将本机端口转发到云端 Phoenix。此通道不访问业务数据库：

```sh
ssh -N -L 127.0.0.1:16006:127.0.0.1:6006 jetaime-server
```

在另一个终端：

```sh
local/eval-replay-venv/bin/python scripts/phoenix_replay.py \
  --snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl \
  --cases local/data/evals/replay/cases-draft-v1.json \
  --experiment A-feat-debug-run1 --repetitions 3 \
  --endpoint http://127.0.0.1:16006
```

先加 `--dry-run` 可仅本地预检，连 SDK 都不会初始化。正式命令会创建或复用由套件/快照哈希命名的数据集，使用 SDK 的真正 task 逐题调用本地 Go 二进制并上传评分，不是把已有结果伪装成实时实验。

Phoenix task 的 Trace Context 传给 Go，Agent/工具/模型成为同一 Trace 的子节点。实验输出包含真实 `traceId`；`eval.case_id`、快照哈希、分支/提交信息也在链路中。独立 Trace 项目为 `jetaime-eval`。默认不上传 Trace 正文，使用 `--capture-content` 可显式打开；数据集本身会包含问题和参考答案，实验输出包含最终答案。完整模型请求与原文保留在 `outputs/evals/replay/` 的私有报告中。

评分包括执行成功、录制完整性，以及已审核题的工具/来源/关键词断言；指标包含供应商 token、累计输入估算、搜索次数和总耗时。参考答案语义正确性仍需人工审核，未添加自动 LLM judge。Phoenix 自身 task 耗时还包含子进程启动和 Trace flush，因此比较 Agent 耗时应看输出中的 `durationMs`。

## 不切分支运行 B、C

启动器支持用 Go 文件 overlay 将**同一份回放代码**编译到指定分支上，不修改 B、C 的源码或提交。真正的 Agent、提示词、工具实现来自目标工作目录；目录注册桥只支持已识别的生产注册形态，未知形态拒绝构建，避免静默跑成A。构建结果记录 `harnessSha256`、工具策略、目标分支/提交/dirty 和二进制哈希。

```sh
local/eval-replay-venv/bin/python scripts/phoenix_replay.py \
  --source-root /Users/bytedance/.codex/worktrees/tool-search-b/Jetaime \
  --env-file /Users/bytedance/Documents/privacy/code/Jetaime/local/.env \
  --model-config /Users/bytedance/Documents/privacy/code/Jetaime/local/models.json \
  --snapshot local/data/evals/snapshots/chat-messages-20261030-154742/messages.jsonl \
  --cases local/data/evals/replay/cases-draft-v1.json \
  --experiment B-run1 --repetitions 3
```

C将 source-root 替换为 `tool-search-c/Jetaime`，实验名改为 `C-run1`。在 feat/debug 目录执行同一版脚本，相同套件会复用同一 Phoenix 数据集版本。每题使用相同录制、相同固定检索、相同模型配置；运行中修改快照、套件、配置或二进制会被拒绝。

2026-10-30：本实验分支已合入 `feat/debug` 的 `1cc0db9`，包含天气 current 逆地理解析和统一回放设施。生产及回放使用本分支的共享工具注册策略。历史报告仍对应合并前代码；正式比较请从这一共同基线重新运行 A/B/C，不复用此前数值。回放工具本身不会自动合并、重置或变基分支。

当前只支持独立问题和固定历史回放，不把生成答案追加成下一题输入；真正连续追问会话回放是后续扩展。已导出的原文和历史评测快照均保持不变。
