# 注册与登录接口

更新：2026-10-14。支持账号密码注册、登录、退出当前设备、当前用户查询与修改密码，使用已有的 users、user_credentials、auth_sessions 三张表；迁移 000002 将账号唯一索引调整为大小写敏感。

## 启动

在仓库根目录运行；连接地址可导出到 shell 或放在被忽略的 `local/.env`：

```sh
export JETAIME_DATABASE_URL='postgres://YOUR_USER@localhost:5432/jetaime?sslmode=disable'
make db-migrate
make dev
```

`make dev` 和 API 二进制默认启用认证，自动启用 PostgreSQL 和 schema 检查，将认证模块注入 Router，无需再传 `-auth` 或 `-database`。显式传 `-auth=false` 时认证及好友群组接口均不注册，只有 `/test/healthz`。如需基础连通性检查，可运行 `make dev API_ARGS='-auth=false'`。认证不依赖模型配置。远端部署通过 HTTPS 传输密码和 Token。

升级已有数据库时先运行 `make db-migrate`，再重启 API。迁移保留已有用户名，不自动将旧账号 `liz` 改为 `Liz`。

## 接口

| 接口 | 输入 | 成功响应 |
| --- | --- | --- |
| POST /api/auth/register | JSON：username、password、可选 nickname | 201，用户 id、username、nickname |
| POST /api/auth/login | JSON：username、password | 200，user、token、tokenType、expiresAt |
| POST /api/auth/logout | Authorization: Bearer TOKEN，无需请求体 | 204，无响应体 |

注册和登录必须发送 `Content-Type: application/json`，请求体最多 8 KiB，只接受一个 JSON 对象，不接受未知字段。认证响应均设置 `Cache-Control: no-store`。

账号为 2–24 位 ASCII 字母、数字或下划线；用户名大小写敏感，注册和登录仅去除两端空白，保留原大小写。昵称去除两端空白、最多 24 个 Unicode 字符，未填或为空时使用账号。注册密码为 6–128 个 Unicode 字符，不要求固定字符组合，不去除空白或转换大小写。`Liz`、`liz`、`LIZ` 是不同账号；登录时必须输入注册时的大小写。注册成功不自动登录。

```sh
# 虚构示例账号，请使用自己的账号和密码。
curl -i http://127.0.0.1:8081/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo_user","password":"example password for demo","nickname":"测试用户"}'

curl -i http://127.0.0.1:8081/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo_user","password":"example password for demo"}'

# 使用登录响应中的 token，不要将实际 Token 保存进仓库。
curl -i -X POST http://127.0.0.1:8081/api/auth/logout \
  -H 'Authorization: Bearer YOUR_LOGIN_TOKEN'
```

登录响应：

```json
{
  "user": {"id": "USER_UUID", "username": "demo_user", "nickname": "测试用户"},
  "token": "RANDOM_LOGIN_TOKEN",
  "tokenType": "Bearer",
  "expiresAt": "2026-10-21T10:00:00Z"
}
```

每次登录创建独立会话，有效期 7 天。退出只撤销提交 Token 对应的会话，不影响其他设备；同一个未过期 Token 重复退出仍返回 204。不存在、格式错误或过期的 Token 返回 401。

错误响应为 `{"error":{"code":"ERROR_CODE","message":"description"}}`：

| 状态 | code | 情况 |
| --- | --- | --- |
| 400 | invalid_input / invalid_json | 注册字段不符合要求，或 JSON 不合法 |
| 401 | invalid_credentials | 账号不存在或密码错误，统一响应 |
| 401 | unauthorized | 退出请求的 Token 缺失、无效或过期 |
| 409 | username_taken | 注册账号已存在 |
| 413 | request_too_large | 请求超过 8 KiB |
| 415 | unsupported_media_type | 注册/登录未使用 application/json |
| 429 | auth_busy | 密码工作槽已满，Retry-After: 1 |
| 500 | internal_error | 内部错误，不返回 SQL、密码或数据库详情 |

## 分层与存储

代码集中在一个业务包 `internal/auth`，按职责拆文件：

- `handler.go`：路由、HTTP 参数解析、状态码和 JSON 响应。
- `service.go`：输入规则、Argon2id、Token 生成及注册/登录/退出流程。
- `store.go`：PostgreSQL 查询与事务，通过 Store 接口供 service 使用。

密码使用 `github.com/alexedwards/argon2id`，参数为内存 19 MiB、两轮、并行度 1、随机盐 16 字节、输出 32 字节。未知账号也进行一次密码哈希验证，降低账号存在性带来的耗时差异。每个实例最多同时执行两项密码工作，超出返回 429；这是资源并发限制，不是按账号或 IP 的防爆破限流。

Token 用 `crypto/rand` 生成 32 个随机字节，编码为 Base64URL。原始 Token 仅在登录响应返回，数据库保存 SHA-256。注册先去除账号两端空白并按大小写精确查询是否占用，重复用户名在密码哈希前返回 `409 username_taken`；两个请求同时通过检查时，由数据库唯一索引保证只有一个创建成功。用户和密码凭据在一个事务中创建，失败不留下孤立用户。退出检查数据库有效期并设置 revoked_at，不依赖清理任务。

Web 登录、注册与登录结果/退出页面位于 `apps/web/`，开发与部署见 [Web 开发说明](../../apps/web/README.md)。首版尚未提供注册邀请码或找回密码；当前用户查询和业务认证见文末新增接口。Assistant 调试模块仍使用模拟身份，其接口不会因开启 `-auth` 自动变成需要登录的接口。

2026-10-14 已在本机 PostgreSQL 执行集成测试，Go 全量 race 测试、vet、lint、17 项评测工具测试通过。实际二进制验证了默认未注册认证路由、显式启用、注册/登录/重复账号/错误密码、重启后退出及重复退出；测试 schema 已删除，结果位于 `outputs/auth-check/result.json`。Linux amd64/arm64 部署包已更新。


## 修改密码与业务认证（2026-10-14）

- `POST /api/auth/password`：Bearer 认证，JSON 为 `{"oldPassword":"旧密码","newPassword":"新密码"}`，成功返回 204。
- 新密码为 6–128 个 Unicode 字符，保留空白与大小写，不能与旧密码相同；错误旧密码返回 `401 invalid_credentials`，不会撤销登录。非法输入返回 `400 invalid_input`，无效 Token 返回 `401 unauthorized`。
- 成功时在同一事务更新 Argon2id 凭据并撤销该账号所有设备的会话。凭据更新使用旧哈希作条件，拒绝并发旧凭据覆盖；登录签发会话时锁定并再次核对已验证的凭据，拒绝改密之前验证旧密码的延迟登录。
- Web 页面 `/page/auth/password/` 提供旧密码、新密码、确认新密码校验；成功后清除本地登录并显示重新登录提示。
- `Authenticate` 每次请求查询数据库的有效会话。好友和群组接口已接入，参见 [好友与群组接口](好友与群组接口.md)。Assistant 调试模块继续使用模拟身份，尚未接入真实群聊天。
