# AI 情侣决策助手 技术方案 V1.0

Go 单体按业务模块组织，CLI 与 HTTP 共用决策服务。先用 Mock 验证 select，再接 PostgreSQL、微信和小程序；业务实体、权限及规划结构以[领域模型与决策契约](领域模型与决策契约.md)为准。

## 1 技术选择

| 层级 | 方案 |
| --- | --- |
| 前端 | Taro + React + TypeScript；微信小程序正式入口，H5 辅助预览 |
| 服务端 | Go，HTTP 使用 Gin；CLI 与 HTTP 仅作入口适配 |
| 数据 | PostgreSQL、建议 pgx + sqlc、版本化 SQL 迁移 |
| Embedding | 本地候选 nomic-embed-text，中文质量与资源消耗待评测 |
| LLM | 本地 Ollama + qwen3.5:9b，模型标签可配置；线上评估 Qwen Flash，统一 Provider |
| 检索 | 空间和类型过滤 + 向量 Top K，保留全量候选对照；按需演进 pgvector、关键词与 Rerank |
| 部署 | Compose 与 HTTPS 起步，服务端管理密钥 |

模型、运行工具和依赖版本接入时核验。候选数量不是强制升级阈值，根据召回、偏好覆盖、Token、延迟和成本调整；不提前引入 MQ、微服务或复杂 Agent。

## 2 模块职责与依赖

实际目录见[项目 README](../README.md)，后续按实现需要增加基础设施包，不创建完整空分层。

| 模块 | 职责 |
| --- | --- |
| cmd/api、cmd/decision | HTTP 与 CLI 入口 |
| auth、space | 身份会话、空间与成员授权 |
| notes、memory | 独立笔记与收藏关系、用户记忆 |
| decisions | 用例编排、上下文、生成校验、决策历史与反馈 |
| app、httpapi | 后续配置与组装、路由及协议转换 |
| ollama | 已实现本地 `/api/chat` 适配、中文提示词与 JSON Schema 输出；CLI 选择注入 |
| telemetry | 可选 OpenTelemetry Go 追踪，OTLP HTTP 上报本地 Phoenix，不改变业务结果 |
| postgres、embedding、llm、wechat | 后续数据库、向量和外部模型/微信适配 |

业务服务不依赖 Gin，外部实现由组装层注入。Embedding、Retriever、LLM Provider 按真实能力定义接口。事务范围由业务操作决定；模型调用不持有数据库事务。图片模块留待 P1，无独立 Plan 模块。

## 3 Workflow 与索引

Request → 身份/空间校验 → 获取实际参与人与适用记忆 → 提取并确认条件 → 空间内候选过滤与 Session 排除 → 完整候选硬约束三态评估 → outcome 判定 → 满足集合召回/Context → LLM → 结构与可信评估校验 → Result/Decision → Feedback/Session 投影。

硬约束独立获取，不依赖向量 Top K；无候选/冲突结论基于完整合法候选池。SelectEvaluation 汇总规则已实现，事实抽取与核验未实现。授权范围先限制，再检索；不能全库召回后只丢弃越权结果。Embedding 记录模型、维度与内容版本，修改后重建，失败标记待重建，不混用不同模型向量；进程重启可恢复或重建索引。

未来按 Task 分发生成与校验逻辑，规划继续共用授权和候选能力，不拆成独立微服务。当前 DecisionService 已实现内存 select runner，CLI 可演示，select 之外的任务在入口明确拒绝。FactChecker 和 Provider 是独立接口；demo.Checker 使用人工定义的虚构事实和有限条件词表，demo.FixedProvider 按软偏好标签排序，不调用模型。暂用完整合法候选池，无 Embedding 或向量召回。

CLI 通过 `-provider mock|ollama` 选择生成实现，默认保留 Mock。Ollama 使用非流式 JSON Schema 输出，关闭思考，默认上下文 8192 token、输出上限 2048 token、请求超时 3 分钟。模型仅接收授权过滤后且硬约束满足的 Context；服务端生成 OptionID 并校验结果。模型服务失败或输出不合法直接返回错误，不自动降级为模拟成功。HTTP 测试服务已验证调用协议与错误处理；真实模型运行及质量评测在模型下载完成后进行。运行命令集中见项目 README。

MemoryStore 在构造时复制固定资料，运行期间不提供 CRUD；每次构建 Context 仍按真实的内存成员、收藏关系和 Memory 使用范围过滤。生成前后通过 store 全局 revision 检查状态，防止晚到结果覆盖反馈；持锁提交历史、Session 与换批命令，Provider 调用不持锁。全局 revision 会使不同空间的并发写也产生保守冲突，这是演示后端的限制；数据库阶段改为适当粒度的版本检查与事务。运行结束所有状态清空，不宣称可恢复进程重启。

本地文件演示支持显式 `reload`：读取并校验新 fixture，以 `WithDataset` 创建独立 Store、保留历史并过期旧会话，使用新 Facts 创建 Checker；当前需求在新服务生成成功后才切换引用。失败时不修改旧 Store。旧换批命令不迁移，历史读取仍依据新资料授权。这是单进程串行 CLI 的资料重载能力，不代表生产 CRUD、持久化或并发热更新已经实现。

## 4 可靠性与评测

反馈、Session 投影和换批命令状态同事务落库，模型生成在事务外；幂等请求可恢复失败的生成，不能把已记录 change_batch 当作生成完成。写操作有幂等标识与版本检查；会话过期、身份变化和取消响应按真实状态处理。限流与 AI 并发隔离随功能实现，模型不可用不阻塞收藏管理。API 错误有 code/message/request_id，不暴露供应商、数据库内部错误或凭证。

首轮固定 50 条 Note 和双方 Memory，对照全量候选、Top K、Memory+Top K；记录模型/提示词/索引版本、召回 ID、Token、耗时与错误。普通测试用固定响应，真实模型评测独立运行；Trace 避免完整私密素材。

本地 CLI 已增加显式 `-trace`，使用 Phoenix + OpenTelemetry Go。每轮生成作为根 span，各步骤记录输入输出、耗时及错误，Ollama 子 span 记录实际 Prompt/原始响应、模型与 Token 数；fixture 内容 SHA-256 区分 reload 前后资料。当前用户授权的本地调试模式包含完整已授权笔记与记忆，但不记录整个 Dataset；生产阶段需另行配置脱敏与保留期限。异步有界导出，观测服务不可用不阻塞业务，CLI 正常退出有独立的限时导出。启动及查看命令统一维护在 README。

线上使用受控数据访问、持久化与外部备份，演练恢复；发布时核对实际账号、域名、权限与审核条件。首轮结构规则已有行为测试，但不代表真实推荐质量、生产权限或语义硬约束已验收。
