# AI 情侣决策助手 V1 开发任务清单

依据：[产品方案](产品方案-V1.0.md)、[技术方案](技术方案-V1.0.md)、[领域模型与决策契约](领域模型与决策契约.md)。本文件只维护任务、依赖、验收和进展。

顺序：CLI 决策 → 数据与 HTTP → 小程序 → 集成发布。V1-01 已有实体类型但规则未定稿；V1-03 仅有 go.mod，尚无 CLI/Provider。其他任务未开始。

## 1 W1 领域与 CLI 决策

| 状态 | 编号 | 任务 | 依赖 | 验收 |
| --- | --- | --- | --- | --- |
| 进行中 | V1-01 | 定义 Note、Memory、DecisionContext、Decision 与空间授权规则 | 无 | 多空间关系、角色授权、Memory 生效、反馈及未知字段规则明确；正文所有权与收藏分离；规划契约保留 |
| 待开始 | V1-02 | 准备 50 条 Mock Note、两人各 10～15 条 Memory 和固定场景 | V1-01 | 餐厅20、菜谱15、活动10、电影5；覆盖硬约束、偏好冲突和未知属性，不包含真实隐私 |
| 进行中 | V1-03 | 初始化 Go 模块、CLI、配置和可替换 Provider | V1-01 | CLI 读取数据并调用决策服务；Embedding 与 LLM 独立接口，测试可用固定替身 |
| 待开始 | V1-04 | 接本地 Embedding，实现空间类型过滤、向量 Top K 和 Memory 获取 | V1-02、V1-03 | nomic-embed-text 候选运行可验证；硬约束全取；越权 Note 不参与检索；向量版本可追踪 |
| 待开始 | V1-05 | Context Builder、Prompt、Qwen 调用、Top 3 校验和 Session | V1-04 | 仅 select，拒绝规划任务；最多3个 Option，仅 Selection；候选与选项ID合法，硬约束通过，换批维护临时排除 |
| 待开始 | V1-06 | 5～10个基础用例与三种检索对照，记录 Trace | V1-05 | 全量、Top K、Memory+Top K 可比较；覆盖硬约束、冲突、漏召、不足和重复运行，记录质量、耗时与 Token |

首轮使用 50 条 Note 和双方各 10～15 条 Memory，并加入多个空间的收藏关系。固定替身可联调，不能代替真实模型效果验收。

W1～W4 是兼职每周15～20小时下的目标顺序，不绑定具体日历日期，也不是上线承诺。资质、模型可用性或审核阻塞时分别记录，不以省略权限和异常处理赶进度。

## 5 完成规则与下一步

任务需有交付文件、验证证据和状态更新才算完成；权限与异常随功能交付，不推迟到发布阶段补做。当前类型包检查仅证明可编译，不代表行为通过。

下一步完成 V1-01 待定规则，准备 V1-02 Mock，并实现 select 校验与 CLI。规划、图片、分享和市场范围集中在产品方案及领域契约维护，本清单不重复展开。
